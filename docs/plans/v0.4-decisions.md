# v0.4 decisions

The contract for v0.4 Browsing and v0.4.1 Art. Every ticket session reads it first. The user decided everything below in the planning interview, the design rounds and the ticket interview (2026-10-19 to 2026-10-20); the mockups and their numbers are in [docs/design/v0.4](../design/v0.4/README.md).

**This is a first version to build, then tune.** The user expects to change a lot of the look, motion and layout once it runs on a real cart. Build it so those changes are cheap: values in the theme and in one place per screen, not scattered through code. When a ticket needs to change anything here that affects the user (a feature, a behaviour, a look, a limit), it says so in its report.

## Scope

- **v0.4:** the new navigation, every screen redesigned, Settings on one page, the Info page, the library index, favourites and recents on SD, clean names and custom names, hidden system files, the 12/24-hour clock and time editor, light and dark themes, and all 18 engine follow-ups from v0.3 (the roadmap lists them). Games show a placeholder box until real art exists.
- **v0.4.1:** real box art (matched and custom), the CRC name database, `just art-scrape` and `just art-add`.

## Navigation

Nothing is kept from the official kernel's keys or screens.

- **Home is a carousel.** Its items, in order: Recent, Favourites, one per console the library found games for (GBA, GBC, GB, NES; later v0.6 systems after NES), SD card, NOR, Settings, Info. Recent and Favourites hide while empty. The ring wraps and takes any number of items (T10).
- **Boot** starts where the "Start on" setting says (T19): Last place (the default: the carousel item and, inside a page, the row), Recent (whose first row is the last game, so A, A resumes), Home, or a chosen item (a console, Favourites or SD card). There is no power-on key to launch a game (T20): keys stay minimal, and L+R+SELECT for Diagnostics is the only power-on combination.
- **Opening** an item zooms into its page. There is no tab bar and no section header: each page has a title bar (the item's 16x16 icon and name on the left, the position or the clock on the right). B goes back to the carousel, facing that item; in SD folders B goes up a folder first.
- **Keys on the carousel:** LEFT/RIGHT turn, A opens.
- **Keys in game lists** (consoles, Recent, Favourites):
  - UP/DOWN move, L/R page by a screenful, and LEFT/RIGHT jump to the previous or next first letter, with a letter card while jumping.
  - A plays and START opens the game popup. SELECT does nothing yet; it is kept free for later (T8). Compact or list with box art is a Settings value.
  - There are no grids and no horizontal carousels of games: there are too many games for them.
- **Game popup:** Play, Favourite (on/off), Clean boot, Boot with addon, Rename, Game info, Delete. It sits beside the selected row, which stays marked, and never covers the title bar. Delete asks in a small centred confirmation with Cancel preselected; it removes the ROM and keeps its save (T11).
- **Popups and confirmations everywhere** follow the same rules.
- **The in-game hotkeys** (L+R+START reset, L+R+SELECT sleep) stay until v0.7 makes them configurable.

## Pages

- **Consoles, Recent and Favourites:** one list card, 8 rows of 14 px. Consoles and Favourites list A–Z (T22), Recent newest first.
  - Rows show the cleaned name, a favourite star, a save dot and the size.
  - Recent and Favourites add a small console marker; Recent shows when each game was played (nothing when the clock wasn't set, T4).
  - List with art shows the placeholder box and two or three facts.
- **SD card:** the card's folders as they are, folders first, with sizes and path pills. A opens or launches; START opens a file popup with Launch, Write to NOR, Add to favourites, Rename, Delete and File info.
- **NOR:** a storage card (used and free of 64 MB), the games card and a Format all row with a confirmation. A launches; START opens Launch, Delete and Game info.
- **Settings:** one scrolling page of section cards: Look, Clock, Games, Cart, Hotkeys, Library, System.
  - A edits a value in place as « value ».
  - Time opens a field editor (UP/DOWN value, LEFT/RIGHT field).
  - The clock is 24-hour by default, with 12-hour as an option.
  - Values are written once, when leaving, as today.
  - Every v0.3 setting carries over except ACCENT (gone with the SD themes) and DIAGNOSE (moves to Info); LANGUAGE stays hidden until v0.9 (T21). New rows: 24-hour clock, the game view (list or list with art), Start on, Show all files, Rescan library. The Box art row waits for v0.4.1.
  - The page explains itself (T25): the selected row's one-line explanation in the hint area, plain-word values (On/Off), the ADDON switches as separate named rows, hotkeys as key chips set by pressing the combination, LED colours as swatches, the theme previewed live, at most 6 rows per section card. Its ticket draws a mockup first for the user's OK.
- **Info:** Controls, In game, Your cart, About (version, build ID, cart revision, FPGA version, card size and free space), and Diagnostics, which moves here from Settings. Each opens a scrolling reading page; Diagnostics runs. The texts are `en_*` strings.

## Look

- **Base:** the "Paper clean" mockups. Warm paper (light) or graphite (dark) surfaces, white or dark rounded cards with soft shadows, a pill-shaped selection, key chips at the bottom, generous spacing. There are no background dots, grids or patterns.
- **Colour per item:** each item has one accent, which colours the carousel backdrop slightly and, on its page, the title icon, the selection pill, the scrollbar and section labels.
  - Values: GBA #4A39B5, GBC #089C94, GB #6B9C10, NES #CE2129, Recent #EF7B21, Favourites #E7529C, SD #297BDE, NOR #E79C10, Settings #637B9C, Info #DEB510.
  - Each accent has base, tint, ink and on values per theme (`palette.json`). Row text on a pill stays neutral ink, and the base colours of Recent, NOR and Info are never used as text (contrast).
- **Torii:** a red torii glyph (#E74A29) sits in the carousel's top-left corner in place of the word TORII. The carousel backdrop itself stays plain.
- **Light and dark** themes share one layout and are built in: SD themes (`theme.ini`), their loader, tools and docs are dropped (T5, T23). The theme switch is a 16-frame top-down wipe if it fits the budget; otherwise a plain instant switch (T18).
- **Icons:** 16x16 and 8x8 for every item and list marker, in one style. The consoles are their hardware silhouettes. The 8x8 GBA and Info icons need another pass.
- **Carousel:**
  - Objects on a ring seen slightly from above, 36° apart. The ring is a window of five slots over the item list, so it takes any number of items (T10); with fewer than five items, only that many slots are drawn, nearest first, and nothing shows twice (T26).
  - Five are visible: the front one lowest and largest, the others higher, smaller (scaled evenly, never squashed) and fading toward the backdrop.
  - Soft ground shadows; no spotlight, glow or frame on the selected object.
  - The name and count sit below.
- **Motion:**
  - A carousel step is 10 frames, ease-out cubic.
  - Opening an item is 12 frames: the object zooms and fades out before the page card rises in, and the title bar slides in. B plays it backwards in 10 frames.
  - A popup opens from its row in 6 frames.
- **Performance comes first** (T9): lists are 14 px rows at 60 fps; if a part of the design can't hold 60 fps, the ticket reports it and the design is adjusted, not the frame rate.
- **Starting a game:** the loading card shows the game's name and a bar for the whole start (0–100 %), which keeps moving on an estimate from the file size while the cart copies the ROM into PSRAM (T17). The status line names only the slow steps: Patching the game, Loading the game, Writing to NOR; the quick checks are only logged (T15, T16).

## Library and data

- **Library index:** a background job scans the whole card by extension into `/torii/library.idx`. It runs again when the card changes (folder dates checked at boot) or from Settings ("Rescan library"); the first scan shows progress.
  - It holds up to 4,096 games, in PSRAM while the menu runs, and is reloaded from the card after a game.
  - It skips the hidden folders.
- **Names**, the first that exists:
  1. your own name (Rename, kept in `/torii/names.txt`);
  2. the CRC database name (v0.4.1; the CRC is computed during a launch, which reads the whole ROM anyway, and by "Identify library");
  3. the cleaned file name: no extension, no `(...)` or `[...]` tags, spaces collapsed, a trailing ", The" moved to the front, and two games that clean to the same name keeping their first differing tag.

  The SD card page always shows raw file names.
- **Favourites and recents** move to `/torii/favorites.txt` and `/torii/recent.txt`, written safely (temporary file, then rename). Today's list, `/SAVER/Recently play.txt` (with its NOR-game entries), is migrated once.
  - `favorites.txt` is one path per line; favourites have no cap and list A–Z (T22).
  - `recent.txt` is `<unix time><TAB><path>` per line, newest first, at most 32 games (T2, T3); its first line, `@boot <item> <row>`, is the boot position. A time read while the clock is unset (before the build date) is stored as 0 and shown as nothing (T4).
- **Rename** (T12): a game's Rename sets its display name in `/torii/names.txt`, leaving the file alone; the SD card page's Rename renames the file and its `.sav` together and updates the index, recents and favourites. Its ticket draws an on-screen keyboard mockup first for the user's OK.
- **Hidden files:** the SD card page and the index hide `/torii`, `SAVER`, `RTS`, `SYSTEM`, dot files, `System Volume Information` and files the kernel can't open. A Settings row, "Show all files", shows everything on the SD card page.
- **Limits:** SD folders list up to 1,024 entries, using v0.3's PSRAM names. Past a limit, a "showing the first N" note appears.
- **PSRAM map while the menu runs** (page 0; a launch overwrites all of it):
  - 0–4 MB: names and the library index;
  - 4 MB: the cover cache;
  - 4.5 MB: reserved (was the SD theme, dropped);
  - 5–6.75 MB: the names database (`names.db`, B21); 6.75–7.5 MB: the CRC cache (`crc.txt`, B21); 7.5–8 MB: reserved for art lookups and v0.9 language tables.
  - Inside 0–4 MB (B3, B5): SD names 832 KB, walk scratch, two library index slots (1–3.5 MB), recents and favourites (3.5–4 MB).

  The user was unsure about fixing this map; revisit it if a later need doesn't fit.

## Art (v0.4.1)

- **Box art**, not cartridge labels: GBA and GB box art is about square, which suits an 80x80 slot, while NES art is portrait and is cropped. It is pre-converted on the PC into the engine's tile format, with no decoding or scaling on the GBA, and loads after the cursor rests.
- **Lookup**, the first that exists:
  1. custom art by file name (`/torii/art/custom/<file name>`, made with `just art-add`), so a romhack never gets its base game's art;
  2. matched art by CRC, then by GBA game code;
  3. the placeholder.
- **`just art-scrape SD_PATH`** fetches libretro-thumbnails box art for the games in the library index, crops it and writes it to the card. Images are fetched on the user's machine and never committed. Check libretro-thumbnails' terms before building it.

## Research

The research behind these choices was done in the planning conversation (DS Style's UI and art, launcher navigation patterns, carousel design, console sprite licences). Its main points:

- DS Style uses one global art style (80x80 box or 120x80 title), raw BMPs looked up by game code, and custom art by file name with a 256-entry cap. Torii keeps the idea and drops the cap.
- Launchers that work with a D-pad open on Continue or Recent, stay at most category, then list, then folder deep, use B consistently for back, and keep tools apart from games.
- No ready-made console sprite set fit an Apache-2.0 repo. The GBA, GBC and GB sprites are redrawn on KyleBing's CC BY 4.0 outlines (credited in `docs/design/v0.4/README.md`).

## Research overrides (conductor, 2026-10-20)

The build's research (`docs/research/v0.4/`) changed these decisions. Each is the conductor's call, for the user to contest.

- **R1 Library change detection (B3):** folder dates don't change when files inside change on FAT (FatFs and Windows never update them; the root has none), so "folder dates checked at boot" is dropped. Boot loads `library.idx` and shows the menu at once, then a background walk (`f_readdir` only) hashes every folder's names, sizes and dates and rewrites the index only when the hash or the volume serial differs. Its write is a background job too. (`research-v04-library.md`)
- **R2 Safe writes (B5, and every user file):** two copies instead of temporary file and rename: write `NAME.bak`, then `NAME`, each ending in a CRC line; at boot use `NAME` if valid, else `NAME.bak`. `f_rename` can leave two names on one cluster chain after a power cut, which FatFs on exFAT then can't delete. A hand-edited file without a CRC line is accepted as is (the user edits these files by hand). (`research-v04-library.md`)
- **R3 Sort order:** A–Z lists sort case- and accent-folded, numbers by value ("Mega Man 2" before "Mega Man 10"), ties by raw name then path. A leading "The" is not ignored: lists sort by the name shown. (`research-v04-library.md`)
- **R4 Name cleaning (B4):** the research's nine rules refine the decisions: underscores become spaces in names without spaces, nested brackets are removed, a 4–5 digit scene prefix ("0001 - ") is dropped, articles in several languages move to the front, stray separators are trimmed, and a name that cleans to nothing keeps its file name. (`research-v04-names-art.md`)

- **R5 14 px rows (B9):** a pixel-pitch tile canvas: row slots 14 px apart in one column-major canvas on BG1 with a fixed map and scrolling by BG1VOFS only, drawn with the existing pixel-y glyph blitter; the pill selection becomes OBJs under the text (it slides by the pixel), not palette-swapped BG tiles. Fallback if it can't hold 60 fps: 16 px slots squeezed to 14 px with HBlank DMA. The spec's VRAM plan for lists is redone in B9. (`research-v04-rows.md`)

- **R6 Carousel sprites (B12):** double-size affine only for the object that zooms; ring slots (scale at most 1.0) use plain affine OBJs, and ground shadows are ordinary sprites in a few pre-drawn widths. Five double-size 64x64 objects would pass the 1,210 OBJ cycles of a scanline and drop sprites. Fog stays per-object palette banks (sprites can't blend with each other). (`research-v04-motion.md`)
- **R7 Theme wipe (B19):** a palette swap changes whole lines, so the 4 px dither edge becomes a hard edge (or a few interleaved lines), done by a VCOUNT interrupt starting HBlank DMA; the theme-dependent colours sit in one contiguous palette run (B1). Fallbacks, in order: a top-down dip through the paper colour with a window and brightness, then the instant switch (T18). (`research-v04-motion.md`)
- **R8 Opening (B19):** the title bar is on BG0 during the open so it can slide sideways while the card rises; the page is drawn hidden in frames 0–4. (`research-v04-motion.md`)
- **R9 Popups (B11):** the popup takes WIN0 and list clipping moves to WIN1; the confirmation's dim brightens toward white in light and darkens in dark, BG0 left out. (`research-v04-motion.md`)

## Tickets

Ordered in waves: every ticket in a wave can run in parallel once the waves before it have merged (a ticket can also start as soon as the tickets it names have merged). The mockup numbers (#1 to #24) are the screens in `pages-light.png` and `pages-dark.png`. Where two tickets in a wave touch one file, the "Files" line says so; the second to merge rebases.

### Rules for every ticket

- **Look values live in one place.** Shared values (surfaces, accents, fonts, row pitch, radii, card and shadow sizes, spacing, every motion's frames and easing) are fields of the built-in themes in `source/ui/ui_theme.c`. Values only one screen uses go in a single `static const struct <screen>_look` at the top of that screen's file (or its own `<screen>_look.h`), named and commented with the spec's unit; the drawing code below it has no bare numbers. A tweak after the first build should be a one-line change, then `just shots-update`.
- **Performance first** (T9): 60 fps on every screen and motion, within `tests/perf/budget.txt`. When part of the design can't hold it, report and propose a change to the design rather than drop frames.
- **Clean from the start** (T1): no interim screens or compatibility layers. Code a ticket replaces is deleted in the same ticket, with its goldens, scripts and strings.
- **Strings** are `en_*` in `source/lang.c`, wired in `LoadEnglish`. Each ticket adds its own block and deletes the strings it orphans.
- **Screens** log `tlog_debug("screen ready: NAME")` when drawn, and their ticket ships their tests (T24): goldens (`tests/shots/NAME.opts`) for the key states in light and one in dark, `-H` hashes over every animation, `frame-cycles` in `tests/perf/budget.txt` (`just perf-update`), and the key-driven scripts that reach their actions, written against the route helper `tests/nav.sh`. Keep goldens few: the look will change, and every golden is re-recorded then.
- **Safety scripts** (`loader_safety`, `nor_safety`, `saves`, `settings`, `stale_recent`) never silently stop testing: from B10 until the page that reaches a path lands, that case prints `SKIP (waiting for Bn)`. The page ticket turns it back on. B20, and any flash to a real cart, fails while a SKIP remains.
- **Menu-only files** go into `NO_COMPAT` in `tools/check.py`. Anything on the launch, save, NOR or boot path stays out of it, so `just check` runs compat.
- **Memory:** EWRAM has about 80 KB free and IWRAM about 2.4 KB of margin over the deepest stack. No ticket adds IWRAM code except B8's hook (under 256 bytes); any new `pReadCache` owner is listed in `source/ez_define.h`. Big tables (index, names, favourites, recents) go in PSRAM page 0, per the PSRAM map above.
- **Kernel NOR** is still written only through `Save_info`. A ticket that changes the keys leading to a NOR writer (settings, NOR write, delete, format) updates `tests/loader_safety.sh` to reach it.
- **Report** any change to what the user sees or to a file format, and log each `source/` change in `CHANGELOG.md`.

### Wave 1: data, assets and engine (no dependencies)

**B1 Palette and built-in themes**
- Scope: `struct ui_theme` gains the eight surfaces (bg, card, edge, soft, ink, ink2, ink3, shadow), `pill_mix`, and the ten accents with base, tint, ink and on per theme, from `palette.json`. The palette banks follow the spec: bank 0 neutrals, bank 1 the current item (base, tint, ink, on, ground tone), bank 2 the four console inks for row markers, bank 3 danger and the NOR bar. Switching item is a bank 1 load; switching theme a palette set, layout unchanged. `tools/palette.py` generates `source/ui/palette.c` from `docs/design/v0.4/palette.json` (committed, like the fonts; a test fails when it is stale), so a colour tweak is an edit to the JSON and `just palette`. New theme fields for the shared look (card radius, shadow offset, pill radius, row pitch, hint chip sizes, margins, every motion's frames) with defaults from `spec.md`. **B21 Names database**
- Scope: `just names-update SD_PATH` downloads libretro-database's `metadat/no-intro` dats for GBA, GBC, GB and NES on the user's machine (cached in a git-ignored folder, nothing bundled or committed), and writes `/torii/names.db`: a header with the dat version, per console a sorted `(crc32, name offset)` array and a string pool, and for GBA a sorted `(game code, name offset)` array from the dats' `serial`. The kernel looks names up by binary search (from PSRAM in the 5–8 MB reserve, or the card), stores full No-Intro names and runs B4's cleaner at display time. CRCs: computed on the PC by `just names-update` (the cart copies a GBA ROM without the CPU, so a launch can't compute one cheaply; B21 deviation), and by Settings' "Identify library" action as a background job, kept in a CRC cache keyed by path, size and date. A CRC miss falls back to the GBA game code, then to the cleaned file name. NES CRCs include the iNES header, like the dats. Fills B4's CRC slot in the name lookup. Report the file formats, the database size and the identify time.
