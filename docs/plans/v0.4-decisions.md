# v0.4 decisions

The contract for v0.4 Browsing and v0.4.1 Art. Every ticket session reads it first. The user decided everything below in the planning interview and the design rounds (2026-10-19 to 2026-10-20); the mockups and their numbers are in [docs/design/v0.4](../design/v0.4/README.md).

**This is a first version to build, then tune.** The user expects to change a lot of the look, motion and layout once it runs on a real cart. Build it so those changes are cheap: values in the theme and in one place per screen, not scattered through code. When a ticket needs to change anything here that affects the user (a feature, a behaviour, a look, a limit), it says so in its report.

## Scope

- **v0.4:** the new navigation, every screen redesigned, Settings on one page, the Info page, the library index, favourites and recents on SD, clean names and custom names, hidden system files, the 12/24-hour clock and time editor, light and dark themes, and all 18 engine follow-ups from v0.3 (the roadmap lists them). Games show a placeholder box until real art exists.
- **v0.4.1:** real box art (matched and custom), the CRC name database, `just art-scrape` and `just art-add`.

## Navigation

Nothing is kept from the official kernel's keys or screens.

- **Home is a carousel.** Its items, in order: Recent, Favourites, one per console the library found games for (GBA, GBC, GB, NES; later v0.6 systems after NES), SD card, NOR, Settings, Info. Recent and Favourites hide while empty. The ring wraps.
- **Boot** returns to where you left off: the carousel item and, inside a page, the row. Holding START at power-on launches the most recent game at once. On a first boot the carousel faces Recent, whose first row is the last game, so A, A resumes.
- **Opening** an item zooms into its page. There is no tab bar and no section header: each page has a title bar (the item's 16x16 icon and name on the left, the position or the clock on the right). B goes back to the carousel, facing that item; in SD folders B goes up a folder first.
- **Keys on the carousel:** LEFT/RIGHT turn, A opens.
- **Keys in game lists** (consoles, Recent, Favourites):
  - UP/DOWN move, L/R page by a screenful, and LEFT/RIGHT jump to the previous or next first letter, with a letter card while jumping.
  - A plays, START opens the game popup, and SELECT switches between the compact list and list with box art.
  - There are no grids and no horizontal carousels of games: there are too many games for them.
- **Game popup:** Play, Favourite (on/off), Clean boot, Boot with addon, Rename, Game info, Delete. It sits beside the selected row, which stays marked, and never covers the title bar. Delete asks in a small centred confirmation with Cancel preselected.
- **Popups and confirmations everywhere** follow the same rules.
- **The in-game hotkeys** (L+R+START reset, L+R+SELECT sleep) stay until v0.7 makes them configurable.

## Pages

- **Consoles, Recent and Favourites:** one list card, 8 rows.
  - Rows show the cleaned name, a favourite star, a save dot and the size.
  - Recent and Favourites add a small console marker.
  - List with art shows the placeholder box and two or three facts.
- **SD card:** the card's folders as they are, folders first, with sizes and path pills. A opens or launches; START opens a file popup with Launch, Write to NOR, Add to favourites, Rename, Delete and File info.
- **NOR:** a storage card (used and free of 64 MB), the games card and a Format all row with a confirmation. A launches; START opens Launch, Delete and Game info.
- **Settings:** one scrolling page of section cards: Look, Clock, Games, Cart, Hotkeys, Library, System.
  - A edits a value in place as « value ».
  - Time opens a field editor (UP/DOWN value, LEFT/RIGHT field).
  - The clock is 24-hour by default, with 12-hour as an option.
  - Values are written once, when leaving, as today.
- **Info:** Controls, In game, Your cart, About (version, build ID, cart revision, FPGA version, card size and free space), and Diagnostics, which moves here from Settings. Each opens a scrolling reading page; Diagnostics runs. The texts are `en_*` strings.

## Look

- **Base:** the "Paper clean" mockups. Warm paper (light) or graphite (dark) surfaces, white or dark rounded cards with soft shadows, a pill-shaped selection, key chips at the bottom, generous spacing. There are no background dots, grids or patterns.
- **Colour per item:** each item has one accent, which colours the carousel backdrop slightly and, on its page, the title icon, the selection pill, the scrollbar and section labels.
  - Values: GBA #4A39B5, GBC #089C94, GB #6B9C10, NES #CE2129, Recent #EF7B21, Favourites #E7529C, SD #297BDE, NOR #E79C10, Settings #637B9C, Info #DEB510.
  - Each accent has base, tint, ink and on values per theme (`palette.json`). Row text on a pill stays neutral ink, and the base colours of Recent, NOR and Info are never used as text (contrast).
- **Torii:** a red torii glyph (#E74A29) sits in the carousel's top-left corner in place of the word TORII. The carousel backdrop itself stays plain.
- **Light and dark** themes share one layout; the theme switch is a 16-frame top-down wipe.
- **Icons:** 16x16 and 8x8 for every item and list marker, in one style. The consoles are their hardware silhouettes. The 8x8 GBA and Info icons need another pass.
- **Carousel:**
  - Ten objects on a ring seen slightly from above, 36° apart.
  - Five are visible: the front one lowest and largest, the others higher, smaller (scaled evenly, never squashed) and fading toward the backdrop.
  - Soft ground shadows; no spotlight, glow or frame on the selected object.
  - The name and count sit below.
- **Motion:**
  - A carousel step is 10 frames, ease-out cubic.
  - Opening an item is 12 frames: the object zooms and fades out before the page card rises in, and the title bar slides in. B plays it backwards in 10 frames.
  - A popup opens from its row in 6 frames.

## Library and data

- **Library index:** a background job scans the whole card by extension into `/torii/library.idx`. It runs again when the card changes (folder dates checked at boot) or from Settings ("Rescan library"); the first scan shows progress.
  - It holds up to 4,096 games, in PSRAM while the menu runs, and is reloaded from the card after a game.
  - It skips the hidden folders.
- **Names**, the first that exists:
  1. your own name (Rename, kept in `/torii/names.txt`);
  2. the CRC database name (v0.4.1; the CRC is computed during a launch, which reads the whole ROM anyway, and by "Identify library");
  3. the cleaned file name: no extension, no `(...)` or `[...]` tags, spaces collapsed, a trailing ", The" moved to the front, and two games that clean to the same name keeping their first differing tag.

  The SD card page always shows raw file names.
- **Favourites and recents** move to `/torii/favorites.txt` and `/torii/recent.txt`, one path per line, written safely (temporary file, then rename). This takes recents writes off kernel NOR. The NOR recents are migrated once.
  - Favourites have no cap and list in the order added; SELECT sorts A–Z.
  - The boot position is saved in `recent.txt`.
- **Hidden files:** the SD card page and the index hide `/torii`, `SAVER`, `RTS`, `SYSTEM`, dot files, `System Volume Information` and files the kernel can't open. A Settings row, "Show all files", shows everything on the SD card page.
- **Limits:** SD folders list up to 1,024 entries, using v0.3's PSRAM names. Past a limit, a "showing the first N" note appears.
- **PSRAM map while the menu runs** (page 0; a launch overwrites all of it):
  - 0–4 MB: names and the library index;
  - 4 MB: the cover cache;
  - 4.5 MB: the theme;
  - 5–8 MB: reserved for v0.4.1 art lookups and v0.9 language tables.

  The user was unsure about fixing this map; revisit it if a later need doesn't fit.

## Art (v0.4.1)

- **Box art**, not cartridge labels: GBA and GB box art is about square, which suits an 80x80 slot, while NES art is portrait and is cropped. It is pre-converted on the PC into the engine's tile format, with no decoding or scaling on the GBA, and loads after the cursor rests.
- **Lookup**, the first that exists:
  1. custom art by file name (`/torii/art/custom/<file name>`, made with `just art-add`), so a romhack never gets its base game's art;
  2. matched art by CRC, then by GBA game code;
  3. the placeholder.
- **`just art-scrape SD_PATH`** fetches libretro-thumbnails box art for the games in the library index, crops it and writes it to the card. Images are fetched on the user's machine and never committed. Check libretro-thumbnails' terms before building it.

## Research

The research behind these choices was done in the planning conversation (DS Style's UI and art, launcher navigation patterns, carousel design, console sprite licences). Its main points:

- DS Style uses one global art style (80x80 box or 120x80 title), raw BMPs looked up by game code, and custom art by file name with a 256-entry cap. Torii keeps the idea and drops the cap.
- Launchers that work with a D-pad open on Continue or Recent, stay at most category, then list, then folder deep, use B consistently for back, and keep tools apart from games.
- No ready-made console sprite set fit an Apache-2.0 repo. The GBA, GBC and GB sprites are redrawn on KyleBing's CC BY 4.0 outlines (credited in `docs/design/v0.4/README.md`).

## Tickets

Ordered in waves: every ticket in a wave can run in parallel once the waves before it have merged (a ticket can also start as soon as the tickets it names have merged). The mockup numbers (#1 to #24) are the screens in `pages-light.png` and `pages-dark.png`. Where two tickets in a wave touch one file, the "Files" line says so; the second to merge rebases.

### Rules for every ticket

- **Look values live in one place.** Shared values (surfaces, accents, fonts, row pitch, radii, card and shadow sizes, spacing, every motion's frames and easing) are fields of `struct ui_theme`, with defaults in `source/ui/ui_theme.c` and a `theme.ini` key each. Values only one screen uses go in a single `static const struct <screen>_look` at the top of that screen's file (or its own `<screen>_look.h`), named and commented with the spec's unit; the drawing code below it has no bare numbers. A tweak after the first build should be a one-line change, then `just shots-update`.
- **Strings** are `en_*` in `source/lang.c`, wired in `LoadEnglish`. Each ticket adds its own block.
- **Screens** log `tlog_debug("screen ready: NAME")` when drawn, get goldens (`tests/shots/NAME.opts`) for their key states in light and one in dark, hash their animations with `-H`, and record `frame-cycles` in `tests/perf/budget.txt` (`just perf-update`). Keep goldens few: the look will change, and every golden is re-recorded then.
- **Menu-only files** go into `NO_COMPAT` in `tools/check.py`. Anything on the launch, save, NOR or boot path stays out of it, so `just check` runs compat.
- **Memory:** EWRAM has about 80 KB free and IWRAM about 2.4 KB of margin over the deepest stack. No ticket adds IWRAM code except B8's measured hook; any new `pReadCache` owner is listed in `source/ez_define.h`. Big tables (index, names, favourites, recents) go in PSRAM page 0, per the PSRAM map above.
- **Kernel NOR** is still written only through `Save_info`. A ticket that changes the keys leading to a NOR writer (settings, NOR write, delete, format) updates `tests/loader_safety.sh` to reach it.
- **Report** any change to what the user sees or to a file format (the decisions above), and log each `source/` change in `CHANGELOG.md`.

### Wave 1: data, assets and engine (no dependencies)

**B1 Palette and theme v2**
- Scope: `struct ui_theme` gains the eight surfaces (bg, card, edge, soft, ink, ink2, ink3, shadow), `pill_mix`, and the ten accents with base, tint, ink and on per theme, from `palette.json`. The palette banks follow the spec: bank 0 neutrals, bank 1 the current item (base, tint, ink, on, ground tone), bank 2 the four console inks for row markers, bank 3 danger and the NOR bar. Switching item is a bank 1 load; switching theme a palette set, layout unchanged. `tools/palette.py` generates `source/ui/palette.c` from `docs/design/v0.4/palette.json` (committed, like the fonts; a test fails when it is stale), so a colour tweak is an edit to the JSON and `just palette`. New theme fields for the shared look (card radius, shadow offset, pill radius, row pitch, hint chip sizes, margins) with defaults from `spec.md`, and `theme.ini` keys for all of them. The v0.3 ACCENT setting and its seven accents go (per-item accents replace them); decide what v0.3.1 SD themes keep (colour keys mapped to surfaces, the wallpaper probably dropped) and report it.
- Files: `source/ui/ui.h`, `ui_theme.c`, `theme_ini.c`, `ui_sdtheme.c`, new `source/ui/palette.c`/`.h`, `tools/palette.py`, `justfile`, `tools/theme_check.py`, `tools/themecheck.c`, `themes/example/`, `docs/themes.md`, `tests/host/test_theme.c`, `tests/kernel/test_theme.c`, a new palette staleness test.
- Tests: host tests for bank building per theme and accent (contrast rules from `palette.json` kept: no Recent/NOR/Info base as text); `tests/themes.sh` and `just theme-check` on the example theme; existing goldens re-recorded only where colours move.

**B2 Icons, sprites and placeholder art**
- Scope: move the sources to `assets/ui/` (icons, sprites, torii glyph) and convert them with `tools/asset.py` into committed engine assets: 16x16 icons as 4bpp OBJ tiles, two per 16-colour bank; 8x8 icons as BG tiles; the carousel objects as 64x64 4bpp affine sprites normalised to about 52 px; ground shadows; the 16x16 torii glyph; the placeholder box for list with art. A `just assets` recipe regenerates them and a test fails when stale. An asset table by item and marker id, so screens never name tile offsets. Use today's 8x8 GBA and Info icons; the user redraws them later, which must be only a PNG edit and `just assets`. Credit KyleBing (CC BY 4.0) next to the generated file and in `README.md`.
- Files: `assets/ui/`, `tools/asset.py`, `justfile`, new `source/ui/art.c`/`.h` (generated data plus the table), `tests/asset_test.py`, `tests/kernel/test_assets.c`.
- Tests: asset round trips in `tests/asset_test.py`; a kernel test that every table entry fits its VRAM budget (OBJ about 16 KB of 32 KB per the spec); a test-kernel golden sheet of every icon and sprite (`#! kernel test`).

**B3 Library index**
- Scope: a background engine job scans the whole card by extension (`.gba`, `.gbc`, `.gb`, `.nes`; the table of extensions to consoles in one place, ready for v0.6 systems) into `/torii/library.idx`: path, size, console, a save flag, name handle. Up to 4,096 games, skipping hidden folders (B4's rule; until B4 merges, a stub). It runs at boot when folder dates differ from the index's (first scan shows progress through `dialog.h`), from a function Settings will call ("Rescan library"), and keeps the menu responsive (steps between frames; PSRAM is hidden while SD mode is on, so copy between FatFs calls as `nameindex.c` does). The index lives in PSRAM while the menu runs and is reloaded from the card after a game. Set the PSRAM page 0 map from the decisions in `source/engine/psram.h` (0–4 MB names and index, 4 MB covers, 4.5 MB theme, 5–8 MB reserved), shrinking `NAMES_BYTES` to share 0–4 MB with the index. API: count per console, the n-th game of a console in name order, lookup by path, total files (for the SD card's "1,204 files"). Past 4,096 games, a "showing the first N" flag. Report the file format.
- Files: new `source/library.c`/`.h` (hardware-free record format, sorting, extension table) and `source/library_scan.c` (the job), `source/engine/psram.h`, `source/nameindex.c`/`.h`, `source/ezkernelnew.c` (boot hook, reload after a game), `source/ez_define.h` if it borrows `pReadCache`.
- Tests: host tests for the format, the extension table, sorting and the cap; kernel tests for PSRAM round trips; a new `tests/library.sh` (a card with nested folders, hidden folders, 4,097 games, a changed folder date that triggers a rescan, the index surviving a launch); compat.

### Wave 2: the look's building blocks
