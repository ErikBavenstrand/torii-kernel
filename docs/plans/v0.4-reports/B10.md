## What changed

- **The new menu replaces the v0.3 screens (T1).**
  - `source/screens/registry.c` is hardware-free and host-tested. It holds the item table: each item's word, accent, 16x16 icon, console and Start on value. Recent, Favourites and the consoles hide while they're empty.
  - It also decides where the menu starts (T19). Start on picks the place, and Last place comes from recent.txt's `@boot` line. If the chosen item is hidden, the menu starts on home facing the nearest item that shows.
  - `source/screens/nav.c` runs the menu's loop:
    - opening a page and going back are plain fades;
    - the page frame is a title bar (the item's icon, name and clock), an empty card and the hint bar;
    - the clock is read every 30 frames and shows nothing while it isn't set (T4);
    - `library_poll` keeps the background walk running;
    - the idle flush writes the log, and the boot position after 5 s idle;
    - a page interface (`struct nav_page`: enter, row, clock, poll; `nav_back`, `nav_defer`) is ready for B12–B17.
  - `source/screens/home.c` is the plain list home shows until B12. It lists the items with what each holds, and the selected row takes its item's accent.
- **`source/actions.c` holds what the pages do, with no screen of its own.**
  - Launches: clean boot, boot with addon, write to NOR (clean or addon), and a Recent `NOR:` entry. Each takes an optional save type and a hard reset.
  - `action_delete_file`: the save stays (T11). The file leaves Recent, the favourites and the library index (`library_forget`). Folders are refused.
  - NOR launch, NOR delete (the latest game) and format.
  - A launch ends the menu's engine session first. If no game starts, the menu comes back where it was.
- **Deleted:**
  - `screens/lists.c`, `setwindow.c`, `setwindow2.c`, `helpwindow.c` and `help_qr.c` (T14);
  - `settings.h`'s page structs, and `PAGE_NUM`;
  - the NOR menu's LOAD SAVE and BACK UP SAVE (`FRAM_save_op`, which isn't in the v0.4 NOR popup);
  - 66 orphaned strings, and 35 goldens with their PNGs.
  - `SET_info_buffer` moves to `settings_store.c`.
- **Dialogs and the loading card use B9's widgets.** Each is a floating card with a hairline and shadow, the title in the heading font, and key chips: "A OK" for a message, "B cancel / A OK" for a question.
  - A hint bar placed anywhere other than the page's bottom now centres its chips in its own height (`ui_paper.c`).
  - A progress bar's paper is now what lies behind it, and its track is always TRACK (`ui_widgets.c`; the one-line comment in `ui.h` says so). The IWRAM copy hook still fills the same tiles.
- **Frame budget:** `UI_DRAW_BUDGET` 250k → 230k. The worst screen entrance is now 243,125 cycles (37.8k margin; it was 268,717).
- **B9's contract:** a list's measure asserts that no other node shares its plane, and that a list over a card shows whole rows. The UI demo's 12 px card now shows two whole rows.
- **Tests:**
  - `tests/nav.sh` provides the routes: `nav_to home|recent|fav|gba|gbc|gb|nes|sd|nor|settings|info`, and `nav_to console X`.
  - Routes into pages (`nav_file`, `nav_game`, `nav_nor_game`, `nav_setting`, `nav_info_page`) fail, naming the ticket that brings them.
  - Actions run through the menu's test hook: `nav_launch PATH [clean|addon|nor|nor-addon] [save=N] [hard] [at=F]`, `nav_delete`, `nav_nor_launch`, `nav_nor_delete`, `nav_nor_format`.
  - The hook takes an action only with its magic word in bits 24–31 and in mGBA, asked again as it runs (`tlog_in_emulator_now`: the debug register must stop answering 0x1DEA when turned off, and answer again when on, so a cart's open bus can't pass).
  - mgba-shot gains `-P FRAME:ADDR:TEXT`, which writes a string.

## Deviations

- **The registry's tests are host tests,** not kernel tests: the code is hardware-free, and CLAUDE.md asks for host tests under ASan and UBSan for such code.
- **`home-start-on`** is one golden (Start on NES, which this card hides). `tests/navigation.sh` checks every Start on value from the log, which avoids nine near-identical goldens.
- **`ui_view_spec.id` isn't dropped.** It would change every view initialiser while B11 edits `ui.h` in parallel. B20 can drop it.
- **Look values** are a `#define` block at the top of `home.c`, `nav.c` (the empty page) and `dialog.c`, plus named `ui_card_config`s. Layout specs need constant expressions, which a `static const struct` field isn't in C.
- **A test hook ships in the kernel:** `nav_test_action` and `nav_test_path`, 516 bytes of EWRAM. It acts only in mGBA and only with its magic word. B13–B15 can keep using it for compat, or replace it with their key routes.
- **The NOR menu's LOAD SAVE and BACK UP SAVE are gone,** because the v0.4 NOR popup has neither (the conductor confirmed they stay dropped). The `.sav` of a NOR game is still copied and loaded as before.
- **The SD listing globals** (`game_total_SD`, `folder_total`) and `nameindex.c` have no menu user until B14.

## Decisions the user may want to contest

- **Home stand-in:** a list on a card. Each row shows the item's name and what it holds: "176 games" (a thousands comma, "1 game"), "1,204 files" for SD card, "0 games" for an empty NOR, "one page" for Settings, nothing for Info. The title bar has the torii glyph, no heading, and the clock. The hints are "^v move" and "A open". The selected row takes its item's accent (pill and scroll bar), so the screen's colour changes as you move.
- **Empty pages:** the item's title bar, a card saying "Coming in a later build", and "B back".
- **Clock:** nothing shows while it isn't set (before 2026-10-01, B5's rule), rather than "--:--". It's read every 30 frames, so a minute change shows up to half a second late. The 12- or 24-hour setting is read again on each screen change.
- **Boot position words:** `recent`, `fav`, `gba`, `gbc`, `gb`, `nes`, `sd`, `nor`, `settings`, `info` for a page (with its row), and `home-<word>` with row 0 for home. Empty pages keep the row they opened on.
- **When the boot position is written:** with the next write of recent.txt (a launch), or after 5 s with no key held while the screen is still. It's tried once per idle spell, so a failing card isn't hammered. A boot that never leaves its start place writes nothing.
- **Start on:**
  - Home faces the first item that shows (Recent when it shows).
  - Last place never set, or an unknown word, gives home facing the first item.
  - A hidden item gives home facing the nearest item in carousel order; on a tie, the later one (Favourites hidden, with Recent and GBA both showing, picks GBA).
- **Motion:** opening and going back are the theme's `UI_TR_FADE` (3 frames out, 6 in) until B19.
- **After an action that started no game:**
  - A failed launch comes back to the same place. It used to go to the SD list or Recent.
  - After WRITE TO NOR the menu stays where it was. It used to go to the NOR list.
  - The error dialogs of a launch show in its own session on black, as before.
- **Dialogs:**
  - A floating card, 208x96, centred, with key chips right-aligned at its bottom: "A OK", or "B cancel" and "A OK". This isn't B11's confirmation with Cancel preselected; B11 or B19 can switch `dialog_confirm` to it.
  - A message with no title leaves the title row blank.
  - The progress bar fills in the current item's base on a soft track.
- **Now reachable only by other means, or not at all:**
  - **Diagnostics:** only by L+R+SELECT at power-on until B17.
  - **The cheat screen, the per-game save type choice, the hard reset (L held) and WRITE TO NOR with addons** have no page until B13 and B14 (the conductor assigned them). `action_launch` already takes a save type, a hard reset and every way to start; `.mde` files are still honoured.
- **Entrances** may land a frame later more often under the lower draw budget.
- **The idle write of the boot position is new:** after 5 s with no key held, the menu writes recent.txt (two safe copies) when the place has changed since the last write. v0.3 never wrote the card while idle except the log.
- **BOOT WITH ADDON with every addon off isn't refused** by `action_launch`: it starts the game clean, as the v0.3 launch path did under that line. B13 greys the entry out.

## Bugs

- **The cheat screen and the save type menu are unreachable** until B13 and B14 (above). `tests/cheats.sh` SKIPs, waiting for B13.
- **Deleting the running log with LOGGING on ends SD logging until the next boot.** This is pre-existing (v0.3 deleted the same way); the next boot logs normally. Repro: set slots 14=1 and 26=2, then `nav_delete /torii/logs/torii-0.log`. The SD card page (B14) may want to hide or refuse `/torii`.
- **Paths that aren't in canonical form launch, and Recent keeps them as given.** `/deep/../Hello.gba` adds a second Recent row for `/Hello.gba`. This is only reachable through the hook; pages pass canonical paths.
- **Diagnostics' first page comes one frame later after the restyled boot notice** (frame 119 instead of 118 on a slow boot). The fixed-frame A presses in the tests were fragile and now wait for the page.
- **B16:** v0.3 flushed the log as SETTINGS opened (the v0.3.2 hang lesson). The Settings page should do the same; `tests/logging.sh hang` SKIPs until then.
