## What changed

- **New `source/screens/sdcard.c`, registered in `nav.c`.** It shows the card's folders as they are (#14, #15).
  - Rows show the raw file name, an 8x8 icon (folder in the item's ink, file in ink3) and a detail: the size ("1.6 KB", "16 MB") or a folder's item count ("176 items", "1 item", "empty", "1,024+ items").
  - Folders come first, then files, each A–Z by R3's sort key. Files sort by their name without the extension, so "Golden Sun.gba" comes before "Golden Sun - The Lost Age.gba"; ties go to the raw name.
  - B4's hidden rule applies unless Show all files is on.
  - Inside a folder, the title bar shows the path as pills ("SD / GBA / RPG", the current one neutral ink on the tint) where the heading was. The root shows "SD card". The right side always shows the position ("4/14").
  - **Keys:** UP/DOWN move; L/R and LEFT/RIGHT page by 8. B goes up a folder, and at the root goes home. A opens a folder or starts a game; with L held it's a hard reset. A on another file (show-all) opens its popup. START opens the file popup.
  - **The popup:** Launch, Clean boot (only while an addon is on: conductor's decision, as B13's Play, so a game that breaks under patches can always start clean), Write to NOR, Write to NOR with addon (only while an addon is on), Add to / Remove from favourites (toggles in place), Delete, File info. Whether an addon is on is read from the settings slots, not the launch's `gl_*_on` copies (those are only read at a launch).
    - Folders get Open and File info. GB/GBC/NES games get no NOR entries. Other files get Delete and File info.
    - Delete asks first in B11's confirmation, Cancel preselected, "Delete NAME?" / "The save stays." (games only). Cancel returns to the popup. After a delete the folder is listed again with the cursor where it was. Folders are never offered Delete.
    - File info is a dialog with the name as title: the kind ("Game Boy Advance game", "File", "Folder"), the size with exact bytes or the item count, the FAT date ("Changed 2026-10-20 14:32"), and "Save: NAME.sav" or "No save yet".
  - **Launch and A:** they use BOOT WITH ADDON when any addon is on, otherwise CLEAN BOOT. Write to NOR is clean; the addon variant is ACTION_NOR_ADDON. Everything goes through `actions.c`.
  - **The cursor is remembered per folder** (the last 16 folders). Going up puts the cursor on the folder you came out of.
  - **Item counts:** an engine job counts each folder's entries while the page rests: after 8 idle frames, not during a popup, dialog, scroll or page change, at most 40k cycles a step, rows near the cursor first. It stops counting at 1,025.
  - **Caps:** up to 1,024 files, and apart from them up to 1,024 folders: past the files' cap the directory is read on for folders only, so every subfolder stays reachable. On a truncated folder's last entry, the hint bar shows "Showing the first 1,024 files" (or "... folders") in place of the key chips; the list holds only real entries, so the cursor and wrap never land on a note, and the position counts only entries. An empty folder shows "Nothing here" in a small label in the card's middle.
  - A listing that fails when the page comes in shows "Can't open the folder" (after the frame), as opening a folder and going up do.
- **New hardware-free `source/sdlist.c`/`.h`** lists a folder into PSRAM (the SD names area, 832 KB, PSRAM map unchanged).
  - The order (u32 offsets) is at the start, then word-aligned records: size, key prefix, flags, count, then the name and its sort key.
  - Building sorts in pReadCache (`READCACHE_SDLIST`, 43 KB at 0x10000 in READCACHE_SAVE's room, listed in `ez_define.h`). It compares 12 bytes of each key in RAM and falls back to PSRAM only for ties.
- **Deleted:** `nameindex.c`/`.h`, `sort.c`/`.h` and their host and kernel tests, `READCACHE_SORT_WORK`, `MAX_files`, `MAX_folder`, and the globals `game_total_SD` and `folder_total`.
- **Lists:** the rows' 8x8 icons use B17's `UI_LIST_ICON8` (a prebuilt tile through `art_icon8_tile`). I had added the same flag; the rebase onto B17 took B17's version, so this ticket no longer changes `ui.h` or `ui_list.c`.
- **Strings:** an `en_sd_*` block, plus `en_hint_menu`.

## Deviations

- **Path pills are in the title bar** in place of the heading, not in the card above the list as #15 draws them. Rectangles are whole tiles and a 14 px list's height must be a multiple of 56 px, so a card can't hold a pill row plus 7 rows. The root has no pills and keeps "SD card".
- **The title's right side shows the position** at the root too (#14 shows "SD:/").
- **The truncation note is in the hint bar** on the last entry, not a row or label: rows took the cursor, and a full-width label cost block-0 tiles the confirmation over a popup then couldn't get. The empty note is a narrow label (18x2 tiles), which leaves the confirmation room.
- **Last place on the SD page** comes back at the root, on the root's row (on the folder you entered, if you were inside one). The folder itself isn't stored in `@boot`.
- **`tests/loader_safety.sh` sets Start on Home** (slot 32=2), because the routes start from home's first row.

## Decisions the user may want to contest

- **Launch and A use BOOT WITH ADDON when any addon is on, else CLEAN BOOT;** Clean boot follows Launch in the popup while an addon is on (conductor's decision).
- **Sorting** ignores the extension first. Folders named like "v1.2" keep theirs.
- **Folder counts** are counted with the same hidden rule, show "empty" for 0 and "1,024+ items" past the cap, and blank while being counted (or if a folder won't open). They are counted again on each visit.
- **Sizes:** 1,024-based, with one decimal under 10 when not whole ("1.5 KB", "2.9 KB"), and "B" for bytes. Files of 4 GB or more read "3.9 GB" (capped).
- **Icons:** folders use the SD ink (blue), not #14's brown; files are ink3.
- **Truncation:** "Showing the first 1,024 files" in the hint bar on the last entry. The 1,024 files are the first the card lists, then sorted, so they aren't necessarily the first A–Z; folders have a cap of their own (1,024).
- **With Show all files on, Delete can remove anything in `/torii` and `/SAVER`** (saves included, and Torii's own lists and index) after the generic "Delete NAME?" question; only folders are refused.
- **Keys:** LEFT/RIGHT page like L/R. B only climbs on a fresh press: holding B doesn't fly up the tree. On a non-game file (show-all), A opens the popup.
- **Remove from favourites** replaces the item's text when the file is already a favourite; the popup stays up.
- **File info** is a plain dialog (A to close), not a reading card.
- **Opening a folder** freezes the old list while it is read (about 0.2 s per 300 files in the emulator), then fades. Worth checking on the cart.

## Bugs

- **Keys pressed while START waits for a page change** to finish (`file_popup`'s wait) still reach the page. For example, B then runs after the popup closes. Harmless; reviewer's nit, not fixed.
- **nav.sh limits** (documented in nav.sh): routes start from home's first row; log lines are cut at 240 characters, so a path of about 225 bytes or more never matches a route's wait.
- **Pre-existing (B10):** deleting the running log ends SD logging until the next boot. The page hides `/torii` unless Show all files is on.
