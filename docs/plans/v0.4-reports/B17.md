## What changed

- **`source/screens/info.c`/`.h`** is the Info page, registered in `nav.c` (mockup #21).
  - Controls, In game, Your cart and About sit on one card. Diagnostics sits on a second card below it.
  - Each row has an 8x8 icon in Info's ink, a name, and what it holds: "buttons, page by page", "hotkeys while playing", "Omega DE, 64 MB NOR", "Torii v0.x.y", "run the checks".
  - The title bar shows "Info" and the position ("1/5"). The hints are A open, ^v move, B back.
  - The list is one 14 px list across both cards. A blank row between the cards is stepped over (UP/DOWN/L/R, wrapping).
- **Reading pages (#22)** use B9's reading view and fade in from the rows.
  - The title shows the page name with a faint "Info" after it, and the screenful at the right ("1/5", the last at the last scroll).
  - The text sits on a card with the scroll bar. UP/DOWN scroll and L/R page. B fades back to the rows, on that page's row.
  - Each page is its own view, so each logs `screen ready: info-controls|info-ingame|info-cart|info-about`.
- **The texts are `en_info[]` in `lang.c`** (`gl_info`, indexed by `enum info_string`). Text filled in from data uses `%s` placeholders, replaced by `fill()` with no printf, so a translation can't break a format.
  - **Controls:** static. Home, every page, game lists (including "L: hold it as you press A" for the hard reset), SD card, NOR, Settings, menus, and L+R+SELECT at power-on.
  - **In game:** written from the actual settings, in the three ways `GBApatch_PSRAM` patches a game:
    - Save states alone: the sleep keys save a state and the reset keys load one.
    - Save states with another addon: the reset keys open the in-game menu.
    - Otherwise: reset and sleep each follow their own switch. With Cheats on, a game with a cheat file still gets the in-game menu.
    - Key combinations are shown as Settings names them ("L+R+START"). The page also covers the START+SELECT wake and when a save is copied to the card.
  - **Your cart:** what the NOR holds (64 MB), games per console and files on the card (library), NOR games and MB used, how many favourites and Recent entries, and what `/torii` and `/SAVER` hold.
  - **About:**
    - Version and build ID.
    - Cart revision (Rev. A LX9 / Rev. B LX16, the same test as `Check_FW_update`) and FPGA firmware.
    - SD card size, free space and file system (`f_getfree`, read between frames after the rows have faded out).
    - Credits: Galmuri (Lee Minseo, OFL 1.1) and KyleBing's icons (CC BY 4.0). The No-Intro/libretro-database (CC BY-SA 4.0) line shows only when `/torii/names.db` exists (B21's `NAMESDB_FILE`).
- **Diagnostics runs from its row.** `nav_defer` ends the menu's session and calls `Diagnostics()`. B on its first page returns, and the shell's `after_action` brings the Info page back on Diagnostics' row. A finished run restarts the kernel as before, and L+R+SELECT at power-on still works. `diag.h` documents both entries.
- **Engine additions** (small and generic):
  - `UI_LIST_ICON8`: a list row with an 8x8 icon (`item.icon`, one 4bpp tile from `art_icon8_tile`) at the row's pad, drawn at any pixel x (`row_icon8`). The name follows after `section_icon_gap`.
  - `ui_title_set_sub`: the title bar's faint after-text in the body font, on the heading's baseline, `look.title_sub_gap` (4 px) after it. It is a setter, not a field of `ui_title_config`, so the parallel tickets' positional initialisers still compile.
  - **B9's review item:** `ui_list.c` no longer sends a no-op `UI_EV_CURSOR` when a `UI_LIST_SCROLL` list at its last scroll gets DOWN. `cursor_limit` clamps the target before the compare. A kernel test covers it.
  - **B7's item:** Diagnostics' `line_add` now refreshes the row of the line leaving its 32-line window, so a cached row can't show old text.
  - `nav_count_words` is exported from `nav.c` (it was a static `count_words`) for the counts with thousands separators.
- **Test seam:** `info_version` and `info_build` (28 bytes of EWRAM) are filled from `TORII_VERSION` and the build ID when Info first opens, unless a golden wrote them first with `-P`. Without that, every build, and every release's version bump, would change the Info goldens. The release workflow runs `just test`.

## Deviations

- **Reading pages use 14 px rows** (8 rows, the game lists' pitch), not the demo's 12 px. A list's rectangle must be whole tiles and, under B9's contract, a whole number of rows: 12 px rows fit only 96 or 120 px, and neither fits the card's 20–140 body.
- **The rows' list is 88 px for 6 rows of 14** (`UI_LIST_FIXED`), whole tiles with 4 px left blank.
- **Headings have no hairline rule after them** as the mockup draws. The reading view has none, and adding one means changing the list's row drawing.
- **Unselected rows keep the list's normal ink** (the mockup draws them in ink2), and every row icon is in Info's ink (the mockup: ink3, with the selected row's in ink). The list draws one way for every row.

## Decisions the user may want to contest

- **All texts:** the Controls, In game, Your cart and About wording above. Controls' "Every page: B back, towards the carousel" covers SD folders and Info's own pages. Hard reset reads "L: hold it as you press A: the game starts with the GBA's boot screen".
- **In game says hotkeys work "in GBA games started with their addons on (Boot with addon)".** It sends Save states and Cheats to Settings, Games, and says a NOR game keeps the hotkeys it was written with. If B13 makes A (Play) start with addons, that line should name it.
- **Controls describes pages not built yet** (game lists, SD card, NOR, Settings) from the decisions doc. B13–B16 and B20 should re-check it when their pages land.
- **Your cart's contents** are my choice; the decisions name only the row.
- **The About row's detail is "Torii v" plus `TORII_VERSION`.** It shows "Torii v0.3.0" until the release sets it.
- **Opening and closing a reading page is a plain fade** (`UI_TR_FADE`), like the shell's open until B19.
- **About reads the card's free space each time it opens.** On FAT32 with a valid FSInfo count that's instant. On exFAT, the first read of a session scans the allocation bitmap while the screen is faded (a few hundred sectors at most; not measured on a cart).
- **On a FAT card without a valid FSInfo free count,** About shows the size and file system and says the free space isn't recorded on the card. Counting would read the whole FAT, seconds on a big card. Not covered by a golden: the test cards' FSInfo is valid.
- **Card sizes are in binary units labelled GB and MB** (1 GB = 2^30 bytes), so a "32 GB" card shows about 29.7 GB.
- **Diagnostics from Info runs from inside a live menu session.** The menu's session is ended first (fade to black), and `library_before_launch` finishes any index or crc.txt write and stops the walk. B on its first page brings the Info page back, and the index loads again in the background.
- **Your cart's counts are read when the page opens.** A library walk finishing while it is open doesn't refresh them. While the index isn't loaded (just after B returns from Diagnostics or a failed launch, or during a first scan), the games section says "Still counting them: open this page again in a moment." instead of 0 games. Not covered by a golden.
- **Rows' 8x8 icons:** keys (Controls), games (In game), cart (Your cart), info (About), system (Diagnostics).
