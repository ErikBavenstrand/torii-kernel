## What changed

- **The rename keyboard, `source/screens/rename.c`/`.h`**, built from the approved mockup (`keyboard-*.png`, `mockups-b16-b18.md`), every number in one `rename_look` table.
  - It takes the opening page's place in the menu's session, in that page's accent, with the page's icon and "Rename" in the title bar.
  - Field card (name, caret, counter, L and R chips; an SD file's locked extension in ink3 after the name), and a 10-column QWERTY grid with digits on top. There's a Latin-1 page and a function row: Shift, àé&, Space, delete, Cancel, OK (solid accent, ink ring when chosen).
  - The keys follow the mockup and research tables:
    - D-pad: a press wraps, a held key repeats (14 f, then 6 f) and stops at the edges. Through the function row the column is kept.
    - A types and repeats like the d-pad. B deletes (16 f, then 4 f) and never cancels, except on an empty field never edited.
    - L/R move the caret (16 f, then 4 f). SELECT is Shift; one capital at the start or after a space turns it off again. START is OK.
  - Caps: names 60 characters, SD stems 100. Past the cap the counter turns red, blinks 6 f, and the hint area says "Names stop at N letters." for 90 f.
  - OK trims the name and refuses an empty one. An unchanged name just closes. Cancel after a change asks "Discard changes?" (B11's confirmation, Cancel preselected).
  - Refusals show in red in the hint area for 90 f, and the keyboard stays open.
- **Drawing.** A new generic widget, `UI_CANVAS` (`ui/ui_paper.c`, `ui.h`), holds pixels a screen paints itself. It has two tile sets that take turns, so a repaint never tears.
  - Each paint knows which set it paints and whether that set is fresh, so the keyboard repaints only what changed since that set last showed. A move repaints its two cells, plus the function row when the selection is in it. The field repaints only the name's line.
  - A whole paint that would pass the frame's draw budget waits a frame, so a first draw takes two frames, as a list's rows may.
  - The shift and delete marks are a 3-glyph font that goes through the IWRAM blitter. Small fills write tile columns directly; text_clear only does large blocks.
  - The keyboard sits on plane 1 (block 1's tiles) over its card on plane 2, which leaves plane 0 to the confirmation.
- **Game Rename** (`screens/games.c`, the popup entry un-hidden) is offered for SD games the index holds, on every console. It starts from the name the game shows.
  - OK writes `/torii/names.txt` through B5's safe file (new `source/gamename_store.c`). Typing the game's own name again (the cleaned or names.db one) removes its line.
  - `library_named` (new, with `lib_rename_shown`) gives the record the new display name and re-sorts its list at once. It also calls `card_changed`, so a walk then rewrites the index. The page comes back with the cursor on the game at its new place.
- **SD Rename** (`screens/sdcard.c`) is offered for files, not folders. `action_rename_file` in `actions.c`:
  - Renames the file. A game's save (`save_name`), `.mde`, `/RTS` `.rts`, `/CHEAT` `.cht` and B22's custom art (`/torii/art/custom/<file name>.bin`) move with it, and a stale `/PATCH` cache under the new name is deleted (it is made again).
  - Then `gamename_store_move`, `userdata_rename` and `library_renamed` run.
  - It refuses, before anything moves: `\ / : * ? " < > |`, control characters, a name ending in "." or a space, and a leading "." (the hidden rule would hide the file). It also refuses another extension or console, a folder, and a name the folder has (`FR_EXIST`).
  - It also refuses a save, save type, save state, cheat file or art already under the new name, which would otherwise be taken from a deleted game, and a save another game in the library shares (the same file name in another folder, or a `.gb` and a `.gbc` of one name).
  - A pending-save record under either name refuses the rename too (`pending_save_named`, new, read-only).
  - A case-only rename keeps its own files; FatFs's `ff_wtoupper` decides what counts as the same name.
  - A move of the save or another of the game's files that fails puts back what moved (the game file last) and reports "The card didn't take it.": nothing is half renamed.
  - **A journal guards against power cuts.** `/torii/rename.txt` (B5's safe file: old path, tab, new path) is written before the first move and deleted after Recent and the favourites follow.
    - At boot, before the library or any launch (`action_rename_recover`, called before `library_boot`), a journal left behind is finished: each file still under the old name moves, then names.txt, Recent and the favourites follow.
    - If the game's file never moved, the rename is undone instead: what moved goes back.
    - A journal that can't be read is deleted.
    - Cost: about 1.3 KB of ROM for the rollback, journal and recovery (kernel `0x9d0a0` to `0x9db98`, strings included), two small files written and two deleted per rename, and two failed `f_open`s per boot.
  - The page comes back listed again with the cursor on the renamed file. If names.txt or the lists didn't follow, a dialog says "Renamed, but not all of its files".
- **Popup room.** The extra item made the Delete confirmation not fit block 0's tiles beside the popup.
  - The empty-page notes are narrower (games 88 px, SD 96 px; the text sits where it did), so the usual popups keep their dimmed popup under the confirmation.
  - When one still doesn't fit (the SD popup's eight items with an addon on, which already failed before B18), `ui_confirm` closes the popup first. The answer then comes back to the page.
- **Memory:**
  - `pReadCache`: `READCACHE_NAMES` (124 KB, names.txt's lines and new text, within one call) and `READCACHE_RENAME` (the last 4 KB, the rename's paths, which outlive the names, user-data and library shares it calls).
  - PSRAM: `PSRAM_NAMES_TEXT_BASE`, 116 KB at 4.5 MB + 16 KB, holding names.txt's old text within the call.
  - The keyboard's state is about 0.4 KB of EWRAM.
- **Strings:** `struct lang_rename` (`gl_rename`), `EN_RENAME_TOO_LONG`.

## Deviations

- The ticket says a game's Rename calls `library_changed`. It calls the new `library_named`, which renames the record's display name in place, re-sorts at once and then starts the same walk: the list shows the new name immediately instead of after the walk.
- SD Rename also moves `.rts` save states and `.pat` patch caches, and refuses on shared saves, pending saves and existing files under the new name. The ticket names only `.sav`, `.mde`, cheats and art.
- `ui_confirm` has a fallback when there is no room over a popup (see above). B11's rule "over a popup, the popup stays, dimmed" still holds whenever the tiles fit.
- Hint chips sit right-aligned as on every page, not centred as in the mockup.
- The ticket's `gamename_custom_*` writer is a new kernel file, `gamename_store.c`. `gamename.c` stays hardware-free and unchanged, and `userdata.c` needed nothing.

## Decisions the user may want to contest

- **Keys:** B never cancels (the approved mockup), so leaving takes Cancel, or START on an unchanged name. Shift turns off after one capital at the start of a word only. A held A types repeatedly; Shift, àé&, Cancel and OK act only on a press.
- **Which games get Rename:** every SD game the index holds, on any console. NOR games and games outside the index (hidden folders) don't.
- **Own name again:** OK on the name the game shows without a custom one (the cleaned or names.db name) removes the names.txt line instead of storing a copy.
- **SD Rename:** files only, no folders (what's inside wouldn't follow); a non-game file (with Show all files) renames alone.
- **Refusals, each with a line in the hint area:**
  - "That name is taken."
  - The file in the way, by kind: "A save of that name is there.", "A save type of that name is there.", "Save states of that name are there.", "A cheat file of that name is there.", "Box art of that name is there.". This also covers an orphaned file of a deleted game, which the renamed game would otherwise take over.
  - "Another game uses its save."
  - "Its save isn't copied yet."
  - "Not with \ / : * ? " < > |" (also for a trailing dot or space)
  - "Names can't start with a dot."
  - "The card didn't take it."
- **Popups:** a game's popup is now Play, Favourite, (Clean boot, Boot with addon), Rename, Game info, Delete. An SD game's is Launch, (Clean boot), Write to NOR, (with addon), favourites, Rename, Delete, File info.
- **Confirmation fallback:** with an addon on, the SD popup closes before its Delete confirmation, and Cancel lands on the list.
- **Narrower notes:** the empty-page notes' rectangles are narrower ("No games here", "Nothing here" unchanged on screen).
- **Speed:**
  - The keyboard's first draw takes two frames, so it comes in a frame later.
  - A move costs about 33,000 cycles. Typing costs up to about 77,000 with a 60-letter name.
  - A whole repaint (the first key, Shift, àé&) costs about 128,000.

## Bugs

- **Before B18:** with any addon on, the SD card page's Delete confirmation over a game's 7-item popup didn't fit block 0's tiles: it logged two errors and never opened, so Delete did nothing. It is fixed by the fallback above (`sd-confirm-tall`).
- **VRAM headroom:** block 0 (planes 0 and 2) on the list pages is nearly full with a popup and a confirmation up: about 9 to 20 tiles spare. Any new plane-2 widget, or a taller popup, falls back to closing the popup. It's worth a look in B20.
- **B22:** after the rebase, a renamed custom art file calls `boxart_forget()`, and the extension comes from `artkey.h`. `artkey.h` has no macro for the custom folder, so `actions.c` spells `/torii/art/custom` itself.
- **tests/boxart.sh (B22's):** its broken-cover case stopped at the first "shown" line, so it depended on the order of two log lines one frame apart. It failed on this branch (the boot runs a frame later) though both lines come and the screens match. It now runs past both.
- **The shared-save check sees only indexed games.** A game the index doesn't hold (in a hidden folder, past 4,096 games, or while the index is still loading after a launch) that shares the save isn't seen, and its save moves with the renamed game.
- **Power cuts during `f_rename`:** an `f_rename` cut short can leave two names on one cluster chain (research override R2). The journal can't prevent that for a file rename, and recovery never deletes either name. If both the old and the new game name exist, it finishes forward and leaves both.
- **names.txt read caps:** the library walk and Rename now both read names.txt up to 116 KB (`LIB_NAMES_MAX` = `PSRAM_NAMES_TEXT_BYTES`). Rename writes at most that, less the CRC line. A hand-edited file over 116 KB is ignored by both, not just by Rename.
- **Self-healing:** after an SD rename of a game with a custom name, or Rename back to a names.db name, the row shows the cleaned file name until the walk (a few seconds) puts the custom or database name back.

## Changelog

- **Rename** in the game and SD file popups, with an on-screen keyboard (10-column QWERTY grid with digits, Latin-1 page, L/R caret, SELECT shift, START OK). A game's Rename sets its name in `/torii/names.txt` and re-sorts its list at once.
