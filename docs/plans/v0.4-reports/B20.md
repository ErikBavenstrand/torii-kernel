## What changed

- **UI walk.** `tests/shots/walk-light.opts` and `walk-dark.opts` share `tests/shots/data/walk.txt`, so `just test` runs the walk in both themes. It visits home and every page by their keys:
  - home turns both ways, wraps, and ends on a held turn;
  - Recent and Favourites open and close;
  - on GBA: moves, a page, a letter jump each way, the game popup closed, then Delete answered Cancel;
  - GB opens;
  - SD card: into a folder, a file's popup, back up;
  - NOR: a game's popup, then Format all;
  - Settings: the theme flips and back (the wipe both ways), a section jump, leaving with nothing written;
  - Info: each reading page.

  Each step waits for its log line ("screen ready", "nav: page X ready", "home: facing X", "popup: closed", "confirm: cancel", "games: letter X", "settings: row N", "settings: nothing changed, not written"). A key that stops working times the run out. The tear watch covers every frame. The run's frame-cycles go to the budget check, and a `kernel error:` line (asserts too) fails it. Its only golden is one hash, of home after the held turn. Three new `tlog_debug` lines make popups, confirmations and letter jumps visible to it.
- **B8's missing golden.** `boot-addon-copy`: BOOT WITH ADDON of a 4 MB game with an emulated copy rate (32 KB a frame). It takes the cart-copy path through a committed PATCH/ file (`tests/shots/data/addon-copy.pat`) and is watched for tears.
- **Info texts re-checked against every page's keys (B12–B19).**
  - L/R page in lists but jump sections in Settings, and NOR doesn't page.
  - The SD card page pages with LEFT/RIGHT too.
  - Hard reset: hold L in a game's menu (as you press A, L pages first).
  - New Rename section; Game info's LEFT/RIGHT changes the save type.
  - In game: A, Play, Launch and Boot with addon start with the enabled addons.
  - Your cart: Write to NOR is in the SD card page's menu.
- **Nothing dead.** Removed:
  - functions with no caller: `ui_wiping`, `ui_dimmed`, `ui_pops_waiting`, `frame_measuring`, `carousel_colours`, `art_load_box` with its tags, `rtc_gettime`;
  - prototypes with no definition (`Progress`, `diag_eeprom_read`, `Show_all_KEY_val`, `Check_cht_file`, `Patch_SpecialROM_sheepmode`, `Find_spend_address_SpecialROM`) and `UI_LETTER_NONE`;
  - the `UI_TR_TAB` transition, used only by the UI demo, which now uses DEEPER;
  - `UI_LIST_ICONS` with `row_icon`;
  - `struct ui_view_spec.id`, with every initialiser;
  - the look fields `content_top`, `edge` and `scrollbar_w`, and the settings section icons (the page has its own table);
  - the `gl_show_Thumbnail` and `gl_ModeB_init` globals;
  - stale comments that named HELP, Recently Played, the SD list, the NOR list, SETTINGS' pages and SD themes.

  Kept on purpose:
  - all strings, `gl_*` and `INFO_S_*` (each has a user);
  - every settings slot (each is read; Mode B and 12 are only stored);
  - `pill_mix` (palette data the host test checks);
  - `UI_TR_SLIDE_X` (a theme effect no transition uses now, cheap to try);
  - the panel styles;
  - EZ-Flash's hardware constants and the commented-out Fire Emblem code;
  - `library_truncated`/`library_games_seen` (logged as a bug: nothing shows the cap).

  `pReadCache`: the rename journal's boot read is now listed in `ez_define.h`. No EWRAM buffer is dead (EWRAM is unchanged).

## Deviations

- The walk is a shots scenario rather than a separate script. It gets the cart setup, the error and tear checks and the budget check for free, and it is a "golden" of one hash.
- The release checklist's cart checks are a new table rather than separate sections.

## Decisions the user may want to contest

- The Controls page's wording:
  - "Starting a game: L, hold it as you pick a way to start in the game's menu … Held as you press A, L pages first, then A starts the game shown."
  - A Rename section, and "the Cancel key leaves it as it was".
  - The SD card page's "L R «» page up, page down".
- In game says A, Play, Launch and Boot with addon start a game with the addons Settings turns on, and Clean boot without.
- `UI_TR_TAB` is gone. A future sideways page change would add a transition back (`UI_TR_SLIDE_X` stays).

## Bugs

Found and not fixed; all are in docs/plans/roadmap.md, v0.4.2, Bugs.

- **Keys during the open zoom reach the page before it shows.**
  - On home, A then A 4–9 frames later starts Recent's first game without the list showing: `-w "nav: home ready" -k @8:A -k @9:- -k @12:A -k @13:-`.
  - START 13–22 frames after A opens the game popup over the page sliding in.
  - A 1-frame B in the zoom is lost while the A after it isn't (`-k @8:A -k @9:- -k @10:B -k @11:- -k @12:A`).
- **START/B mashed 3–4 frames apart over a game popup** can drop a START and pass the next B to the list, which goes home. Not reachable by hand.
- **An empty SD folder still shows the hints** "A open · START menu".
- **No page shows the library's 4,096-game cap note.** `library_truncated` and `library_games_seen` have no caller.
- **Eight icons are never drawn:** the 8x8 Favourites, Recent, SD, Settings, torii and up icons, and the 16x16 file and folder icons.
- **`action_launch`'s result is ignored by all three callers.**
- **The SD card page's count job** costs up to 194k cycles a frame (within a frame).
- **Settings' Mode B is only stored.** The kernel never reads it, as in v0.3.
- **The walk uses 55 of mgba-shot's 64 waits** (`MAX_WAITS`).
