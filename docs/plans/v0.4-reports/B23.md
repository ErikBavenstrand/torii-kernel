## What changed

- **`just art-scrape SD_PATH`** (`tools/art_scrape.py`, standard library plus Pillow 13.0.0 through `tools/art.py`):
  - **Games:** the walk from `names_db.walk_card` (the kernel's hidden folders, dot files, depth cap), plus any game the library index (`/torii/library.idx` or `.bak`, read with `tests/library_idx.py`) lists that the walk missed and that is still on the card.
  - **CRCs:** `names_db.update_cache` over every game. It keeps the CRCs in `crc.txt` that are still valid and writes `crc.txt` like `names-update` does, so the kernel finds the new art at once. `--dry-run` only reads.
  - **Dats:** B21's cached dats in `dist/dats`, downloaded if missing (`--offline` never downloads).
  - **Match chain:**
    1. Custom art (`/torii/art/custom/<file name>.bin`, ASCII case folded as `artkey.c` folds it) is kept.
    2. Art already on the card is kept: `/torii/art/<CRC32>.bin`, or for GBA `<game code>.bin`, which a new CRC file would hide.
    3. The CRC's No-Intro name, looked up in the console's dat. A `.gb` or `.gbc` file is also looked up in the other one's dat, and then uses that console's thumbnails.
    4. For GBA, the game code's dat name.
    5. For each name: `&*/:`<>?\|"` become `_`, then the tool tries `https://thumbnails.libretro.com/<System>/Named_Boxarts/<name>.png`, then the name cut at its first `(`.
  - **Output:** each picture is converted with `art.convert` and written as `/torii/art/<CRC32>.bin` (uppercase hex, `boxart.c`'s `%08lX`), through a `.part` file and a rename.
  - **Polite fetching:**
    - One request at a time, 0.5 s apart (`--delay`), with a User-Agent.
    - A 5xx is retried 3 times (after 5, 10 and 20 s), then fetching stops for the run. A 429 or a network error stops it at once.
    - 404 and 410 go to `dist/art-cache/misses.txt`; `--retry-missing` asks again.
    - Only bodies that start with the PNG signature are cached. A cached picture Pillow can't read is deleted.
  - **Cache:** pictures go to `dist/art-cache/<System>/<name>.png` (git-ignored), so a second run sends no requests for what it has.
  - **Report:** the hit rate per console, with counts: downloaded, from the cache, already on the card, custom, not in the dats, no thumbnail, not fetched. Then a list of the games without art, pointing to `just art-add`.
  - **Options:** `--dry-run` downloads no pictures, writes nothing to the card or the cache, and prints the URL it would fetch for each game. `--offline`, `--console GBA,GB...`, `--cache`, `--dats`. Hidden options for tests: `--base-url`, `--retry-wait`.
  - **Help text:** says box art has no licence grant, is fetched on the user's PC for their card, and must never be committed or published. The justfile comment and the README row say the same.
- **Recipe and docs:** the `just art-scrape` recipe; `just test-host` runs the new tests; a README row next to names-update and art-add. `tools/check.py` gets rules for the scraper (lint, test-host) and for `tests/library_idx.py` (now also test-host).

## Deviations

- **Games come from the walk plus the index, not the index alone.** The ticket says the index "or" a walk. The index misses games copied on the PC since the cart last booted, and the walk uses the kernel's hiding rules. Games the index lists that the walk missed are added.
- **The scraper writes `crc.txt`**, as `names-update` does. Without it, the kernel couldn't match new art by CRC until Identify library or a later boot.

## Decisions the user may want to contest

- `art-scrape` rewrites `/torii/crc.txt`, computing CRCs it doesn't have. It reuses B21's rule that a CRC is kept only when its date matches, so right after `names-update`, before the cart has booted, CRCs are computed again.
- **A GBA romhack missing from the dats gets its base game's box art** through the game code. This matches B21's names. Custom art (`art-add`) overrides it.
- **Existing `/torii/art/<game code>.bin` counts as art on the card:** no CRC art is written over it.
- **Politeness defaults:** 0.5 s between requests. A 5xx is retried 3 times after 5, 10 and 20 s, then fetching stops. A 429, a timeout or a connection error stops fetching for the run at once (a rerun picks up from the cache). Thumbnails the server lacks (404) are remembered in `dist/art-cache/misses.txt` until `--retry-missing`.
- `--dry-run` still downloads the dats if they aren't cached (needed to match), but never box art.
- **Art is never re-fetched or replaced once it is on the card.** To refresh it, delete the file. There's no `--force`.
- **Output format:** one line per console (for example `GBA: 4 games, 3 with art (75%): 2 downloaded, 1 from the cache, 1 not in the dats`), then the list of games without art and the request count.

## Bugs

- None found and left open. Minor known limits:
  - On macOS's case-insensitive disk, two No-Intro names that differ only in case would share one cache file. This is very unlikely.
  - A single timeout or connection reset stops fetching for the run. The ticket allows retries only on 5xx.
