## What changed

- **`source/library.c`/`.h`, hardware-free.** The extension table (`library_console_of`; `Check_file_type` now calls it), the sort key, and the index image: header, records, sorted order, folder table and string pool. Also the builder, a sliced merge sort, queries (n-th game of a console, path, find, counts) and in-place updates (`lib_forget`, `lib_rename`).
- **`source/library_scan.c`, the kernel side.** It is one state machine, stepped by a job between frames, or in a loop at boot and before a launch.
  - **Boot** (`library_boot`): loads `/torii/library.idx` into PSRAM. With no index, a bad one, or another card's (volume serial), it does the first scan and its write before the menu. A progress dialog appears once the scan takes more than 30 frames.
  - **Menu job** (`library_poll` in the lists loop): walks the card with `f_readdir` only. It hashes every folder's game names, sizes and dates, the `/SAVER` names and the volume serial.
  - **Rebuild:** only when the hash differs does a second walk build a new index in the other slot, sort it and switch to it. `library_generation()` changes and the frame wakes. A job then writes the file.
  - **Launch** (`library_before_launch`, at the start of `Game_boot` and `Boot_NOR_game`): finishes a pending write, with a progress bar, then forgets the index. The menu loads it again after a failed launch, and the next boot loads it after a game.
- **API for B12, B13, B14 and B16:** `library_count`, `library_game`, `library_name`, `library_size`, `library_flags`, `library_path`, `library_find`, `library_total_files`, `library_truncated`, `library_games_seen`, `library_forget`, `library_renamed`, `library_rescan`, `library_ready`, `library_busy`, `library_generation`.
- **PSRAM page 0 map** (`engine/psram.h`):

  | From | Holds |
  | --- | --- |
  | 0 | SD list names (`NAMES_BYTES` shrinks to 960 KB) |
  | 0.94 MB | the walk's 64 KB scratch (save hash table, sort buffer) |
  | 1 MB | two 1.25 MB index slots, to 3.5 MB |
  | 3.5 MB | left for B5's user data, as the conductor asked |
  | 4 MB | covers |

- **B4 is used** for the display name the lists sort by (`gamename_clean`) and for the hidden rule (`gamename_hidden`, with the same flags the SD card page will pass).
- **`cover_loading()`** was added to `engine/cover.c`, so the walk waits while covers load.
- **The SD list (`lists.c`) hides the root `torii` folder**, which every card now has. The decisions say the SD card page hides it; B14 brings the rest of the hidden rule.

### File format (`/torii/library.idx`, little-endian, version 1)

| Section | Size | Contents |
| --- | --- | --- |
| header | 64 B | magic `TLIB`, version u16, header size u16 (64), record size u16 (16), flags u16 (bit 0: truncated), record count u16, folder count u16, games per console u16 x 8 (GBA, GBC, GB, NES, 4 spare), total files u32, pool bytes u32, walk hash u32, volume serial u32, body CRC32 u32, games seen u32, reserved u32, header CRC32 u32 |
| records | 16 B each | folder u16, flags u16 (bits 0-3 console, bit 4 has save, bit 5 gone), size u32, name u32 (bits 0-23 pool offset of the file name, bits 24-31 half the distance to its sort key), key prefix u32 (first 4 key bytes, big-endian) |
| order | u16 each, padded to 4 | record numbers sorted by console, then by name: each console's games are one A-Z run |
| folders | u32 each | pool offset of each folder's path (`/` for the root) |
| pool | padded to 4 | NUL-ended strings on halfword boundaries: file name then sort key per game, and folder paths |

- **Writing:** the header is written last and stays blank until then. A cut write therefore leaves a file the boot rejects.
- **Loading:** a bad magic, version, size, CRC or body check means a full scan.
- **When the version must change:** with any change to the layout, the sort key or B4's cleaning, since the stored order depends on them.
- **Reading it on a PC:** `tests/library_idx.py FILE [--header]` lists the index.
- **Size:** about 100 KB for 1,000 games with No-Intro-length names, 180-420 KB for 4,096.

### Sort key (R3)

- The key comes from the name shown (B4's cleaned name). ASCII and Latin-1 letters are case- and accent-folded (é to e, ß to ss, Æ to ae), and Latin Extended-A letters lose their accents.
- Each run of digits sorts by value ("Mega Man 2" before "Mega Man 10"). Other UTF-8 sorts after z.
- Ties go by raw file name, then folder path. A leading "The" counts.

### Measured walk times (emulated)

- **Speed of emulated SD:** reads ~336 KB/s (the cart measured 1,710 KB/s) and writes ~40 KB/s. The I/O parts are therefore several times slower than on a cart. CPU parts (name cleaning, keys, sort) take the same time as on a cart.

| Card | First scan (boot) | Sort | Write | Later boots: load | Later boots: background check |
| --- | --- | --- | --- | --- | --- |
| 1,000 games, 42-char names, 9 folders | walk 3.2 s | 0.4 s | 100 KB in 2.3 s | 0.3 s | 2.1 s wall |
| 4,097 games, 42-char names, 9 folders | walk 13.2 s | 2.0 s | 422 KB in 9.4 s | 1.3 s | 8.6 s wall |
| 4,097 games, short names (`tests/library.sh`) | walk 3.5 s | | 180 KB in 4.6 s | 0.56 s | 3.5 s wall |

- **Where the build time goes:** about 2.5 ms per game of CPU. Most of it is B4's `gamename_clean` plus the sort key (my stand-in cleaner took about 0.6 ms). See the decisions below.
- **Cart figures:** still to be recorded on a real cart. The walk logs `library: ... walk: N entries, F folders, ... in T ms` for that.

## Deviations

- **R1 and the walk:**
  - R1 is implemented in two passes. The background walk only hashes; a second walk builds when the hash differs. An unchanged card thus costs no name cleaning, PSRAM writes or sort.
  - The first scan's write runs at boot. In the background it would wait for the menu to rest, and a card powered off first would scan again.
- **The fingerprint covers games and folders only.** Non-game files and folder dates are left out, so the kernel's own files (logs, patches, cheats) never trigger a rewrite. `/SAVER` names are in it, so a new save updates its game's save dot, at the cost of one background rewrite after a game's first save.
- **Extension matching is now exact.** The extension table matches the last extension: `x.sgb` and dot-less names like `romgba` no longer count as games or launch. The old suffix match accepted them.
- **The SD list hides `/torii` now (in `lists.c`),** ahead of B14.
- **Depth cap:** folders deeper than 8 levels aren't indexed.

## Decisions the user may want to contest

- **First scan dialog:** appears only when the scan takes over half a second. It reads "Library" / "Looking for games on the card", with "N games found" as the status line.
- **Write at launch:** if the index changed and hasn't been written yet, a launch first shows "Library" / "Saving the game list" with a bar (up to ~2 s for 4,096 games on a cart).
- **Big first scans are slow.** A first scan of 4,096 games takes roughly 15 s plus I/O, mostly in B4's cleaner. A background rebuild of a changed big card takes twice that while the menu runs.
- **Another card:** an index with a different volume serial (a card swapped, or files copied to a new card) is rebuilt before the menu rather than shown.
- **Nearly full cards:** the index isn't written while the card would keep less than 1 MB free (when FatFs knows the free space). Such a card scans at every boot.
- **What "total files" counts:** what the SD card page would show (B4's rule), so it equals the game count unless hidden rules change.
- **Save dots:** a save counts when `/SAVER` holds the name the launch path uses (`.sav` for GBA, `.esv` for emulated games). A GB game's `.sav` doesn't count.

## Bugs

- **Wide folders make the walk quadratic.** `f_opendir` with a full path makes FatFs scan the parent from its start for every subfolder.
  - Found by the adversarial tester with 2,050 root folders, one game each: the first scan took 84 s and the background check 96 s.
  - A single step can then last several frames.
  - Normal cards (tens of folders) aren't affected.
  - The fix needs a small helper in the vendored FatFs, to open a folder from the parent's directory entry. Not done.
- **Menu changes don't update the index yet.** `library_forget`, `library_renamed` and `library_rescan` have no callers. A delete or rename in today's SD menu leaves the index stale until the next boot's walk. B10, B13, B14, B16 and B18 must call them.
- **The walk can't save the index on some cards.** With `/torii` as a file or a write-protected card, every boot logs the error and does the first scan again.
