## What changed

- **New hardware-free module.** `source/gamename.c` and `source/gamename.h`. Nothing in the kernel calls it yet: B3 and the pages will. It is in `NO_COMPAT`.
- **Cleaning.** `gamename_clean(out, path)` cleans file names and `gamename_clean_title(out, name)` cleans names that have no extension (the v0.4.1 CRC names). Both follow the research's nine rules; the deviations are listed below.
- **Collisions.**
  - `gamename_same` says whether two cleaned names collide.
  - `gamename_cmp` is the matching sort order, so B3 can sort, then group runs.
  - `gamename_dedupe(out, paths, count, self)` appends the tags that tell a game apart. `out` must already hold its cleaned name.
- **`/torii/names.txt`.**
  - `gamename_custom_parse` indexes the file. It sorts line offsets with a heap sort; the caller supplies the array, at most `GAMENAME_CUSTOM_MAX` = 1024 lines.
  - `gamename_custom_get` looks a path up by binary search.
  - `gamename_custom_set` writes the whole new file into a buffer. `gamename_custom_move(old, new)` does the same for a renamed file (B18), in one pass and one write. It returns `GAMENAME_UNCHANGED` when the old path has no custom name.
  - Failures have separate codes: `GAMENAME_TOO_BIG`, `GAMENAME_INCOMPLETE` (writing would lose names) and `GAMENAME_BAD_PATH`. `GAMENAME_FAILED(len)` tests for any of them.
  - The I/O sits behind `struct gamename_io { read, write }`, used by `gamename_custom_load`, `gamename_custom_store` and `gamename_custom_store_move`. B5's safe write plugs in there. B3, B13 or B18 add the FatFs read adapter when they first call it; I added no adapter now, because it would be dead code.
  - The text is only ever read, so it can live in PSRAM.
- **Display name.** `gamename_display(out, path, custom, crc_name)` tries the custom name, then the CRC name, then the cleaned name, and returns which source it used. `crc_name` is the v0.4.1 slot: pass NULL until then.
- **Hidden rule.** `gamename_hidden(dir, name, flags, show_all)`. The flags are `GAMENAME_DIR`, `GAMENAME_ATTR_HIDDEN` and `GAMENAME_OPENABLE`; the caller sets `OPENABLE` from B3's extension table.
- **Tunable tables.** The article table, the "tags kept on collision" table and the hidden root folders are short arrays at the top of `gamename.c`.

### names.txt format

- One game per line: `<path from the root>` TAB `<name>` LF.
- On reading:
  - CRLF and a UTF-8 BOM are accepted.
  - Lines that don't start with `/`, have no tab, or have a blank name are ignored.
  - When a path appears twice, the later line wins.
  - Paths compare without ASCII case.
  - Names are trimmed and cut to 255 bytes.
- On writing:
  - First come the non-name lines (comments, notes), unchanged and in their order. Then one line per game, sorted by path.
  - Blank lines, the BOM, CRLF and blank-name lines are dropped.
  - Control characters in a name become spaces. A blank name removes the line.
- A file that can't be read, or that has more than 1024 entries, still loads but is never written over (`complete` = 0).
- A read that fills the buffer exactly also counts as failed, because the file may go on. The adapter's buffer must be larger than any names file it accepts.

## Deviations

- **Rule order.** Rule 7 (stray separators) also runs before rule 6 (articles), not only after it. With the research's order, "Game, The - (Disc 1)" kept ", The"; now it becomes "The Game".
- **Long names.** A name longer than 255 bytes is cut first, as every other name path does, so a cut can leave half a tag, which then stays as text.
- **The "tags kept on collision" table.** It is a preference, not a filter: when two names differ in several tags, a tag in the table (a revision, Beta and so on) is shown instead of the first difference.

## Decisions the user may want to contest

1. **Release-number prefix.** Only 4 or 5 digits followed by a dash are dropped ("0001 - Game" becomes "Game"). 3 digits stay, so "007 - NightFire" is untouched. 4 digits from 1900 to 2099 stay because they read as a year ("1943 - The Battle of Midway"). The cost: about 200 GBA scene releases numbered 1900 to 2099 keep their number.
2. **Articles.** The table is The, A, An, Le, La, Les, L', Der, Die, Das, El, Los, Las, Il, Lo, Gli, De, Het, Een. Matching is case-sensitive, and only before the first " - ". An article inside a subtitle or a compilation part stays where it is ("2 Games in 1 - Incredibles, The + ..."). "Game,The", with no space, stays.
   - **Known false positive:** a title that really ends in ", A" or another listed article moves it too: "Rock, Paper, A" becomes "A Rock, Paper".
3. **Tags shown on a collision.**
   - Each game shows the tag at the first place where it differs from each other game.
   - Tags in the kept-tags table (Rev, v1.1-style versions, Beta, Proto, Demo, Sample, Virtual Console, T+ and T- translations) win over an earlier difference. So "Game (Europe) (En,Fr) (Rev 1)" shows "(Rev 1)" rather than the language list, and "Game (USA, Europe)" next to "Game (USA) (Rev 1)" shows "Game" and "Game (Rev 1)".
   - A game with no tag where the other has one shows none.
   - Every tag shows in parentheses, whatever its brackets: "[!]" shows as "(!)" and "[T+Eng_v1.0]" as "(T+Eng v1.0)". Underscores become spaces only in names whose underscores cleaning turned into spaces.
   - **Known weak case:** because a kept tag wins, a game can lose its region tag. "Game (USA) (Rev 1)" next to "Game (Europe)" shows as "Game (Rev 1)" and "Game".
   - Collisions ignore ASCII case, so "Super_Game_(J)" and "super game (U)" collide.
4. **Same tags.** Games whose tags are identical add their folder's name when they are in different folders ("Game (Hacks)"); a game in the root adds nothing. When they share a folder, they add their extension instead ("G (gb)", "G (gbc)").
5. **Names that clean to nothing.** These keep their file name without the extension ("(Unlicensed)"). "0001 - (U)" cleans to "0001".
6. **Underscores.** They become spaces only in names that have no spaces at all.
7. **names.txt behaviour.** See the format section above: the later line wins, a write sorts the entries after the notes, and a file over 1024 entries or one that can't be read is never written over.
8. **Hidden entries.**
   - Root folders, matched without case: `torii`, `SAVER`, `RTS`, `SYSTEM`, `System Volume Information`, plus `PATCH` and `CHEAT`, which I added because the kernel keeps its own files there.
   - Dot files and folders anywhere, which also covers macOS's `._` files and `.Trashes`.
   - Entries with the FAT hidden or system attribute, as v0.3 already hid them.
   - Every file the kernel can't start, which also hides `.sav`, `.txt` and `.cht` files on the SD card page.
   - "Show all files" shows everything.
