## What changed

- `source/settings_model.c`/`.h` (hardware-free, host-tested): the Settings page as data. Seven sections (Look, Clock, Games, Cart, Hotkeys, Library, System) with an 8x8 icon id each, and 25 rows with a label, a one-line explanation, a value kind (choice, on/off, number, time, date, key combination, colour, action) and their slots. A working copy of the slots (`struct settings_values`) with `settings_get`, `settings_set`, `settings_step` (LEFT/RIGHT, wrapping), `settings_set_keys` (a combination as pressed), plain-word values (`settings_value_text`), visibility (LANGUAGE hidden, the LED colours only while the LED is on) and a section's visible rows. A value set back to what it was puts back the slots as loaded, so a visit writes the NOR only for a real change. The clock: a field editor (hour, minute and AM/PM; year, month, day; wrapping, month lengths), the 12/24-hour formatter, the date formatter, the weekday, and BCD conversion for the RTC.
- `source/settings_store.c` (declared in `settings.h`): `settings_load` (slots and the RTC), `settings_stage`, `settings_commit` (one write through `Stage_SET_info`/`Commit_SET_info`/`Save_info`, then applies the launch switches, LED, strings, DIM and LOGGING), `settings_read_clock`/`settings_write_clock`, `settings_write_edit` (a field editor's result over the clock read again, so a page left open doesn't put the clock back), and `settings_log`, a boot debug line with the new settings. The v0.3 `Settings_run` commits through `settings_commit`, so the existing settings cases in `tests/loader_safety.sh` cover the new writer.
- New slots in `source/ez_define.h`: 30 24-hour clock, 31 game view, 32 Start on, 33 Show all files.
- `source/lang.c`: an `en_set_*` block (section names, labels, explanations, option names), as `gl_set_*` arrays indexed by the model's enums.

## Deviations

- The 8x8 icon id is on the section, not the row: the mockup (#18-#20) draws icons only on section labels. Rows carry no icon.
- The ticket's file list didn't name a kernel-side file; the reading, staging and writing went into `source/settings_store.c` so `settings_model.c` stays hardware-free.
- Hotkeys take 2 or 3 keys, not the research's 2 to 4: the in-game patches read exactly three slots (`Hotkey_value`). A two-key combination stores its last key twice.
- `settings_commit` doesn't apply the theme: the page previews it live (B16) and the menu's next session reads it. A live preview must stage (or set the theme itself), since the theme is read through `Read_SET_info`.
- B16 refreshes the Time and Date rows by calling `settings_read_clock` every few frames, and cancels an edit with `settings_restore`.
- The research's per-section "Reset X" rows and an "Animations" row aren't in the table: they aren't in the decisions. Both would fit the 6-row cap.

## Decisions the user may want to contest

- **Sections and rows:** Look: Theme, Game view, Start on, Dim screen. Clock: Time, Date, 24-hour clock, Clock for games. Games: Fast patching, Auto save, Save states, Cheats. Cart: Rumble for games, Mode B, LED, LED colour, SD card light. Hotkeys: Reset hotkey, Reset keys, Sleep, Sleep keys (Save state keys and Load state keys while Save states is the only one on, as in v0.3). Library: Rescan library, Show all files. System: Logging (Language hidden).
- **Texts:** new labels and values are in sentence case ("Last place", "List + art", "On"); each explanation is at most 38 characters. "Mode B" is explained as "What the cart is in a DS (mode B)." from its options (Rumble, RAM, Link); check the wording.
- **Start on** stores Last place 0, Recent 1, Home 2, Favourites 3, SD card 4, GBA 5, GBC 6, GB 7, NES 8 (later consoles append). An unknown value is Last place.
- **Hotkeys:** a combination needs 2 or 3 keys including L, R, START or SELECT, and can't equal, hold or be held in the other hotkey's (the smaller would fire first); Sleep can't be START+SELECT, the keys that wake a game. Shown as "L+R+START". Two-key combinations such as START+A pass the rule.
- **Time editor:** hour and minute only, with an AM/PM field in 12-hour mode; the hour cycles 12, 1 ... 11 within its half of the day (so 11 AM, UP gives 12 AM, midnight) and AM/PM moves it by 12; setting the time zeroes the seconds. The date edits year, month, day (2000-2099), shown 2026-10-20; the weekday is worked out, not edited (v0.3 had a weekday field).
- **LED colours:** eight named colours (Off, Blue, Green, Cyan, Red, Magenta, Yellow, White) from the RGB bits; the SD card light defaults to Off as in v0.3 (its three bits were 0).
- **Dim screen:** Off, 1, 2, 5, 10, 15, 30, 60 min; a value stored by v0.3 between them (say 7) shows as "7 min" and steps to its neighbours.
- **Theme:** Dark or Light; a card that still says SD theme (2) reads as Dark until changed.
- The boot logs the new settings at debug level ("settings: 24-hour clock On, game view List, start on Last place, show all files Off").
