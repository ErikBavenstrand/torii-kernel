## What changed

- **One bar for the whole start (T15, E16).** Each launch step owns a share of the bar, set as constants in one `enum` in `source/ezkernelnew.c` (`LAUNCH_SAVE` 5%, `LAUNCH_STATES` 10%, `LAUNCH_SCAN` 80%, `LAUNCH_PATCH` 90%, `LAUNCH_COPIED` 95%, `LAUNCH_NOR_SAVE` 50%). The status line no longer shows a step's percentage, for any progress dialog, saves included.
- **Status only for the slow steps (T16, E18).** The statuses are "Loading the game" (from the start of a launch), "Patching the game" and "Writing to NOR". The quick checks call `progress_step(NULL, lo, hi)`: the bar moves, the status stays, nothing waits for a draw, and the caller logs the step. Creating the save file and the save state file are now log lines. Creating the save state file also moves the bar per block, which covers its ~2 s. Six orphaned strings are gone (`en_check_sav`, `make_sav`, `check_RTS`, `make_RTS`, `check_pat`, `make_pat`), along with `ShowbootProgress`.
- **The cart's copy (T17, E15).** `progress_cart_copy` (`source/progress.c`) wraps `Send_FATbuffer(…, 0)`:
  - It gets the bar's VRAM layout (`dialog_progress_pixels` → `ui_progress_pixels`) and installs `progress_copy_vblank` with `irqSet`.
  - That handler is IWRAM code of **124 bytes** (well under 256), with no calls and its state in EWRAM. It fills bar pixels on a fixed-point estimate from the file size at `PROGRESS_COPY_RATE` (64 KB a frame, one constant).
  - The estimate is fast to 90% of the copy's share by the expected time (`PROGRESS_COPY_KNEE`), then runs at an eighth of that speed (`PROGRESS_COPY_SLOW`). It never goes past the step's end.
  - Afterwards the handler is removed and the widget is told where the fill ended (`ui_progress_drew`).
  - Each launch logs `launch: the cart copied N KB in F frames, B bytes a frame (the estimate: E frames)` for tuning on the cart.
- **The NOR write's title (E17).** The card's title is the game's name, for launches and NOR writes alike. The NOR write's status says "Writing to NOR".
- **Emulator:** the cart model takes `OMEGA_COPY_RATE=BYTES` (bytes a frame). The port then reads 0 until the copy's time is up; unset, the copy is instant as before. `tests/shots.py` gained `#! env NAME=VALUE`.
- **Docs:** `docs/research/omega-de-hardware.md` (the launch note: IRQs during the copy, the hook, `OMEGA_COPY_RATE`) and `docs/release-checklist.md` (check the bar on a big CLEAN BOOT; tune `PROGRESS_COPY_RATE` from the log line).

## Deviations

- The status line has no percentage anywhere, which also covers "Saving to SD card" and BACK UP SAVE. E16 picked the bar, and I applied that to every progress dialog rather than to launches only.
- `ui_widgets.c` and `ui.h` gained `ui_progress_pixels` and `ui_progress_drew`, a small engine API the ticket's file list didn't name. The hook needs the bar's tiles.
- `source/GBApatch.c` (`Check_RTS`) changed. The ticket's file list doesn't name it, but the save state file's status had to go and its creation now moves the bar.

## Decisions the user may want to contest

- **The card's title is the game's file name**, extension included, in the heading font, cut with "…" when long. The text line under it is empty.
  - Before, the title said "Loading..." and the file name sat in the text line.
  - The empty text line leaves a gap above the bar. B10 restyles the card anyway.
  - The NOR write uses the same card: title = name, status "Writing to NOR" (E17).
- **"Loading the game" shows from the very start of a launch**, through the save check, before the ROM copy starts.
- **The bar's shares** (above): the save takes 5%, the save states another 5%, the load runs to 90% (95% with nothing to patch), and the patching takes the rest.
- **The copy estimate:** 64 KB a frame (about 3.8 MB/s: 4.4 s for a 16 MB game). This is a guess: nothing has measured the real cart's copy yet. If the copy is slower, the bar crawls over its last 10% and then waits at the step's end. If it is faster, the bar jumps ahead when the copy ends. The release checklist tunes it.
- **The full bar still holds a fifth of a second** before the game starts, as in v0.3.
