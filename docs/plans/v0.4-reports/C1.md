## What changed

- **L and R do nothing in game lists or on the SD card page.** A new list flag, `UI_LIST_NO_SHOULDERS`, makes the list ignore them. Holding L and pressing A now hard-resets the selected row: L no longer pages first. LEFT/RIGHT still page on the SD card page and still jump by letter in game lists. The NOR page had no L/R conflict and is unchanged.
- **The save dot is now an 8x8 floppy save mark.** It is drawn in B2's one-colour icon style (`assets/ui/icons8/save.png`, `ART_ICON8_SAVE`); `dot.png` and `ART_ICON8_DOT` are gone. The gap between the mark and the size went from 2 to 4 px (`row_dot_gap`, `ui_theme.c`). Consoles, Recent and Favourites all show it, in both views.
- **GBA boot mode setting.** It is the first row of Settings' Games section, with two values: With addons (the default, today's behaviour) and Clean. It lives in the new slot 35 (`assress_boot_mode`); an erased or unknown value reads as With addons. The slot is written with the others when you leave Settings, so there is no new NOR writer.
- **Per-game boot mode** in Game info, below Save type, with three values: Default, With addons, Clean. UP/DOWN pick the Save type or Boot mode line, and LEFT/RIGHT change it. Changes are written when the page closes; the save type and the boot mode are written separately, so one failing keeps the other.
- **How A starts a game.** A and Play in game lists, and A and Launch on the SD card page, now pass `ACTION_DEFAULT`. `action_launch` resolves it after reading the game's `.mde`: the game's own mode if it has one, otherwise Settings'. If the mode is With addons but none of the four addon switches is on, the game boots clean, as the SD card page always did. GB, GBC and NES always start clean, and NOR games ignore the mode. Clean boot and Boot with addon in the game popup stay explicit one-off choices. Each launch logs `launch: boot mode clean|with addons (the game's|Settings')[, none on]`.
- **Info and README.** Info's Controls and In game texts and the README describe the new keys and the boot mode. Game info's hints are now "^v move · «» change · B back". The game lists' hint chips never mentioned L or R, so they are unchanged.

### Storage format

The per-game mode is **byte 1 of the game's existing `/SAVER/<name>.mde`**:

- **Layout:** byte 0 is the save type, as before. Byte 1 is the boot mode: 0 Default, 1 With addons, 2 Clean; any other value reads as Default. The file stays 16 bytes.
- **Compatibility with older kernels:** v0.3 and the official kernel read only byte 0, so the format stays compatible with them. They write zeros past byte 0, so their files read as Default.
- **Writes:** the writer (`mde_write` in `GBApatch.c`) reads the file, changes one byte and writes it back, so a launch that changes the save type keeps the boot mode. A failed read now writes nothing.
- **Renames:** the `.mde` file already moves when a game is renamed, so the boot mode follows.

## Deviations

- **The SD card popup shows one alternate way to start a game, not both.** It shows "Clean boot" when Launch would start with addons, and "Boot with addon" when Launch would start clean (by the game's mode or Settings'). Showing both would need 9 items, and a popup holds at most 8 (`UI_POPUP_ITEMS`). Working this out reads the game's `.mde` (`action_game_facts`) each time the popup opens on a GBA file while any addon is on.
- **No game-list hint chips changed:** none mentioned L or R.

## Decisions the user may want to contest

- **Save mark:** a solid 7x7 floppy in ink2, 4 px left of the size: a clipped top-right corner, a shutter window with its slot, and a label window. It was redrawn after the conductor's review because the first outline drawing read as a document beside `ICON8_FILE`. In list with art it sits alone at the row's right end.
- **Setting wording:** "GBA boot mode" with the values "With addons" and "Clean". It is the first row of Games, explained as "How A, Play, Launch start GBA games."
- **Game info wording:** "Boot mode" with the values "Default", "With addons" and "Clean". Default doesn't say what Settings' mode currently is.
- **Game info keys:** UP/DOWN switch between Save type and Boot mode (either key goes to the other line), and the picked value shows « ».
- **Play (and A, Launch) with every addon off now takes the clean path:** `GBApatch_Cleanrom` runs, logged as ", none on". Before C1, Play went down the addon path with no patches; the SD card page's A already booted clean.
- **The two popups differ:** the game popup always offers both Clean boot and Boot with addon, while the SD card popup shows only the alternative to Launch.
- **A NOR game ignores the boot mode,** global and per game: its addons are fixed when it is written.
- **The mode is a two-value choice** (With addons, Clean), plus Default per game. It is not a list of which addons to use.
- **SD card popup's "Boot with addon" skips the cheat screen.** The game popup's entry of the same name opens the cheat screen when Cheats is on and the game has a cheat file. SD's Launch with addons skipped the cheat screen before C1 too.
- **Bogus byte 1 left on the card:** a byte 1 the kernel doesn't know (from a hand edit) shows as Default and stays in the file until another mode is picked.
- **L and R are unbound on the SD card page too:** it had the same L+A conflict as the game lists. LEFT/RIGHT still page there.
