## What changed

- **Settings saves on confirm** (`source/screens/settings_page.c`). A value is written to the kernel NOR when it is confirmed: A ending an in-place edit, or a hotkey capture accepted.
  - It is written only if the working copy differs from what the NOR holds. The write is the same as before: stage, then `settings_commit`, one `Save_info` sector erase and program in `[0x780000, 0x7C0000)`.
  - The hint bar shows "Saving..." (new `en_set_saving`) and the page stays up. The write runs once that text is on screen and any theme wipe has ended, or after 30 frames at most. The last frame stays on screen during the write's few hundred ms; there is no black pause.
  - The write never runs from a key, so a held key's repeat can't stall a scroll. Keys act at once while it waits; it runs from the page's poll once the page is still, or after 30 frames with no key held. An edit opened meanwhile goes in with its old value, not its preview.
  - B while a write waits runs the write first (a running theme wipe ends at once), then the page goes. Leaving never pauses on black.
  - B on an edit, B on a capture, a refused hotkey, and a value confirmed unchanged write nothing. Time and Date still set the clock at once.
  - The leave hook no longer commits. It puts back an edit left open, with its preview, and writes a change still waiting (only reachable from the test hook).
  - New `ui_wiping()` in `ui.h`.
- **Boot position** (`nav.c`, `registry.c/.h`, `userdata.c/.h`, `userdata_store.c`):
  - `recent.txt` keeps `@boot <item>`, the carousel item last faced, and never a page or row.
  - Start on **Last place** starts on home facing that item, or the nearest shown one if it is hidden.
  - Leaving a page, launching from it, or turning home sets the item.
  - Older lines read as their item: `@boot gb 3` and `@boot home-gb 0` both mean GB.
  - Recent, Home and a chosen item keep their T19 meaning: Recent and a chosen item open their page.
  - A boot where nothing moves writes nothing. Opening the start item's page counts as moving, so a launch from it is recorded.
  - `nav_page.row` stays: it brings a page back on its row after an action.
- **Docs:** README (how Settings saves; power-on faces the last item) and `docs/release-checklist.md` step 5. Info's Controls text doesn't describe either behaviour, so it is unchanged.

## Deviations

- The `settings-last` golden and its perf scenario are gone (see Tests). The Settings page now always opens on Theme, so its heavy first draw on Sleep keys can no longer happen.
- The `nav: start on N: PLACE` log line no longer ends in `, row R`.

## Decisions the user may want to contest

- **Wear (your choice):** each confirmed change is one sector erase of the kernel NOR's settings sector. v0.3.2 had moved the writes to leaving the page to save wear, and B16 kept that. Toggling a row five times now erases the sector five times; a change and back is two erases.
- **"Saving..." in the hint bar**, for at least a frame and up to the end of a theme wipe (16 frames). During the write itself the screen is frozen for a few hundred ms on a real cart. The emulator writes at once, so the length on a cart is unmeasured.
- **Keys while a write waits** act at once; the write follows once the page is still. B writes first, then leaves (cutting a theme wipe short).
- **The hint bar shows only "Saving..."** while a write waits, even if you have moved to another row or opened an edit meanwhile.
- **Settings always opens on Theme**, at power-on too: Last place no longer returns to a Settings row.
- **A failed write isn't retried:** the page keeps the value on screen and the log has the error, as before.
- **A power cut** between A and the write (at most 30 frames, usually 1–2) loses that one value.
- **Last place and Start on:**
  - Last place never reopens a page or row: launching from page 3 of GBA brings you back facing GBA on home.
  - Recent and chosen items still open their page, as T19 says.
  - With Start on Recent, sitting on the Recent page writes nothing. Leaving it writes `@boot recent` for a later switch to Last place.
- **Older boot lines** are kept until you move: `@boot home-gb 0` stays on the card, still read as GB, until the next change.

## Bugs

- **`tools/analyze-baseline.txt` flakiness (pre-existing):** clang-tidy's `bugprone-not-null-terminated-result` on `source/gamename.c` comes and goes between runs. `just analyze-baseline` drops it, and the next `just analyze` reports it as new. I kept it in the baseline.
- **A redundant SD write (pre-existing, from the adversarial tester):** a boot that turns away from its start item and back rewrites `recent.txt` with the same `@boot` line at the idle flush. `userdata_boot_set` compares the new item with the last one set, not with the one on the card. Harmless; it costs one SD write.
- **Capture ending on B (pre-existing):** B pressed on the same frame a hotkey combination is let go counts as part of the hold. The page stays open, and the capture still saves correctly.
