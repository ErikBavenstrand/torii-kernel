## What changed

- **Romhack rule (kernel):** a game is named and boxed by its CRC only.
  - The GBA game-code fallback is gone from `names_db_name` (`source/namesdb.c`) and from box art's lookup (`source/boxart.c`). It gave a romhack its base game's name and art.
  - Art named `<CODE>.bin` is no longer parsed (`source/artkey.c`).
  - `names_ids` became `names_crc`.
  - A CRC miss now keeps the cleaned file name and the placeholder art, unless the user adds a custom name or custom art.
  - `LIBRARY_VERSION` 3 → 4, so every card's index is rebuilt (sort keys of former code-named games change).
- **Romhack rule (PC tools):**
  - `names-update` writes `names.db` without a game-code table, and its summary says "N keep their file names (not in the dats: romhacks, translations, other dumps)".
  - `art-scrape` takes art by game code only for a *patched dump* of a listed game:
    - Its cleaned file name must equal the code's dat title (`names_db.code_match`).
    - Its tags beyond the dat name's may only be a GoodTools region, `[!]` or an 8-digit checksum.
    - It writes that art under the file's own CRC, which the kernel reads.
    - "Pokemon - Radical Red.gba", "Metroid Fusion (Hack).gba" and "Mother 3 [T-Eng].gba" get no art.
  - **v0.4.1's romhack art:** v0.4.1's art-scrape gave a romhack its base game's box by game code, written under the romhack's own CRC (`/torii/art/<CRC32>.bin`), which the CRC-only kernel would still show. art-scrape now deletes such files: `<CRC32>.bin` of a game on the card that it finds no art for (no CRC match in the dats, GB/GBC tables crossed, and no patched-dump match). `--keep-stale` and `--dry-run` only list them; custom art is never touched.
  - Files named like game codes (`<CODE>.bin`, which v0.4.1's kernel read but no tool wrote) are reported as not read.
  - `tests/library_idx.py` (which art-scrape uses to read the index) follows version 4, and a test pins it to `source/library.h`.
- **`just art-add SD_PATH [FOLDER]`** (`tools/art.py`): converts every picture in the card's `/torii/art/custom-src` (or FOLDER), into `/torii/art/custom/<file name>.bin`.
  - **Picture types:** png, jpg, jpeg, gif, bmp, webp, tif, tiff, in the folder itself (not subfolders).
  - **Matching:** a picture's name, less its extension, must be a game's file name on the card, with or without the game's extension, NFC and case folded (`Pokemon - Glazed.png` → `Pokemon - Glazed.gba`).
  - **Report:** each picture → game, the pictures that matched no game, doubles (two pictures for one game: the first by name that converts wins), and pictures that failed to convert (exit 1).
  - **Re-runs:** the art takes its picture's date, so a re-run converts only changed pictures. `--force` converts all (needed after changing `--align`), `--dry-run` none.
  - The one-game form `just art-add ROM IMAGE SD_PATH` is kept: the recipe is now `art-add +args`.
- **`just names-add SD_PATH FILE`** (`tools/names_db.py add`): sets many games' own names at once in `/torii/names.txt`.
  - **Input:** lines of "file name (with or without extension, any case) or /path, a tab, a name". An empty name removes the game's own name; `#` lines are skipped.
  - **Write:** through the two-copy CRC format. The tool keeps existing names and comments, sorts and folds as the kernel does, and refuses more than 1,024 names or more text than the kernel reads. Names are cleaned as Rename cleans them (`rename_edit_result`): ASCII control characters dropped, spaces at the ends trimmed.
  - When names.txt has no comment line yet (a new file, or one with only names), it adds the header comment `# Torii's own names: a game's path, a tab, its name`.
  - On the cart, names are set with Rename; names-add is the PC's way to do many at once.
  - **Report:** what was named, and lines that named no game. `--dry-run` writes nothing.
- **Rename:**
  - **Confirmed:**
    - A custom name (Rename's or names-add's) wins over the dats' name in console lists.
    - It names a romhack: Rename is offered for every SD game the index holds.
    - It holds when the index is rebuilt: the walk hashes names.txt, so a PC edit also rebuilds the index.
  - **Discoverability:** Info's Controls, under Rename, now says "In a game's menu, Rename gives the game a name of your own in its lists, in place of its file's or No-Intro's: a romhack's too. On the SD card page it renames the file."
- **README** rows for names-update (CRC only), names-add, both art-add forms, and art-scrape's new rule; the Game lists paragraph gives the name order and the romhack rule.

## Decisions the user may want to contest

- **CRC only, with one exception on the PC.** The kernel never uses a game code. art-scrape uses the code for art only when the file's title equals the base game's and its tags are only regions, `[!]` or a checksum. So a dump renamed with your own tag ("(Erik)") gets the placeholder: give it custom art.
- **Names have no exception.** A patched dump under the official title already shows that title, because its cleaned file name matches the dat's.
- **art-scrape deletes v0.4.1's romhack art by default:** any `/torii/art/<CRC32>.bin` of a game on the card that it would give no art (a romhack that v0.4.1 gave its base game's box). Art you put there by hand for such a game goes too; custom art belongs in `/torii/art/custom` (`just art-add`), which is never touched. `--keep-stale` keeps it.
- **Files named like game codes** (`/torii/art/<CODE>.bin`) are ignored by the kernel; art-scrape reports them and leaves them.
- **The art-add folder:**
  - The default folder is on the card (`/torii/art/custom-src`, hidden from the menu), so the source pictures take card space. Another folder can be given.
  - A picture without the game's extension goes to every game with that base name, for example `Tetris.png` to both `Tetris.gb` and `Tetris.gbc`.
  - Two pictures for one game: the first by name that converts wins, the other is reported and skipped.
  - A changed `--align` needs `--force` to redo pictures already converted.
  - Subfolders aren't read.
- **The names-add format:** tab-separated, matched by file name with or without extension, any case, and every copy of that file name on the card gets the name. Names go through Rename's rules (ASCII control characters dropped, spaces at the ends trimmed, at most 255 bytes). A `# Torii's own names...` header comment is added to a names.txt that has no comment line, including an existing one with only names.
- **The Info Controls wording** for Rename (above).
- **Index rebuild:** `LIBRARY_VERSION` 4 rebuilds every card's index once after updating.
