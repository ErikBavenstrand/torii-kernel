## What changed

- **The direct save/load mode is gone.** The `Patch_RTS_only` branch is deleted from both patch-selection places in `source/GBApatch.c` (PSRAM and NOR). `Patch_RTS_only`, its five `GBApatch.h` externs and `source/gba_rts_only.s` are deleted too. With Save states on, the launch always uses `Patch_RTS_Cheat`, the in-game menu. `Patch_length()` already reserved `RTS_PATCH_LENGTH` whenever Save states was on, so the trim arithmetic is unchanged.
  - **Size:** the ROM is 2,072 bytes smaller (646,240 → 644,168) and IWRAM has 1,392 bytes more free (4,620 → 6,012). EWRAM went from 22,424 to 22,432 bytes free.
- **The Hotkeys rows:**

  | Row | Label | Explanation |
  |---|---|---|
  | `SET_RESET_ON` | Back to menu | "Hold the keys to leave a game." |
  | `SET_RESET_KEYS` | Menu keys | "Held together in game. A sets them." |
  | `SET_SLEEP_ON` | Sleep | "Screen off. START+SELECT wakes it." |
  | `SET_SLEEP_KEYS` | Sleep keys | "Held together in game. A sets them." |

  - **No row renames itself any more.** `save_keys` and `label_of` are gone, along with `SET_LABEL_SAVE_KEYS`, `SET_LABEL_LOAD_KEYS` and the settings page's `keys_label` tracking.
  - **Save states on:** Back to menu shows **On** (display only; the stored value is kept) and its explanation reads "Opens the in-game menu instead." A on the row does nothing. The new `settings_reset_armed()` decides this.
  - **Cheats on alone:** Back to menu keeps its own value and reads "With a cheat file: the in-game menu."
  - **Games section:** Save states reads "Save and load from the in-game menu."; Cheats is unchanged ("Applies a game's cheat file.").
  - **Unchanged:** the setting slots and the defaults (Off, L+R+START, Off, L+R+SELECT).
- **Info → In game:** the direct "# Save states" paragraph (`INFO_S_INGAME_STATES`) is deleted. Save states on shows the in-game menu paragraph; Cheats alone keeps its cheat-file line. "# Back to the menu" is now "# Back to menu", and its Off text says "turn Back to menu on". The Sleep paragraph now shows in every case.
- **Docs:** `docs/research/hook-coverage.md` (the mode is recorded as removed), `docs/release-checklist.md` and `docs/plans/v0.4-manual-test.md` use the new names. README never described the old mode. `v0.4-decisions.md` describes only the arming, not the direct mode, so it is unchanged.

## Deviations

- **Cheats alone doesn't show Back to menu as On.** The brief said the row shows On when Save states *or* Cheats is on. But Cheats arms the menu only in a game with a cheat file; in other games, Back to menu's own value decides. So with Cheats alone the row keeps its value and its explanation says "With a cheat file: the in-game menu." With Save states on, it shows On, as the brief says.
- **The CHANGELOG entry is not written.** Per the protocol, the lines are below for the conductor to add.

## Decisions the user may want to contest

1. **Back to menu can't be edited while Save states is on.** It shows On, and A does nothing; the explanation says why. Turn Save states off to change it. Its stored value is kept and comes back when Save states goes off.
2. **The Cheats-alone wording:** "With a cheat file: the in-game menu." The value stays editable (see Deviations).
3. **Compat's in-game menu column and `tests/logging.sh` debug now test Save states alone** instead of Save states with Reset. Save states with Reset goes through the same code.
4. **Games already on the NOR keep the patch they were written with.** A game written with Save states alone by an older kernel still has the direct keys (the Sleep keys save, the Menu keys load) until it is written again. Info already says a NOR game "keeps the hotkeys it was written with". Worth a line in the release notes.
