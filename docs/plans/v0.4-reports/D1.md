## What changed

### Round 1: was Start on broken? No.

- **Your cart's logs** (copied read-only from `/torii/logs`; boots of this exact build, id `F0044D26`) show each boot starting where its setting said:
  - Start on was **GBA**, from an earlier build, so the GBA page opened.
  - You then confirmed **Favourites** in Settings (written at 32.5 s), so the next boot opened Favourites.
  - Last place was never the setting on this build. Booting into a page looked like the old Last place, but it was T19's "a chosen item opens its page".
- **Emulator, end to end:** every value held through real power cycles, A-launches from the GBA, Recent and SD card pages, the in-game Reset hotkey, and a power-off after 5 s idle.
- **One real flaw, fixed (`8b7b1bc`):** C3's redundant write.
  - Opening another item's page, leaving it and turning back rewrote `recent.txt` with the same `@boot` line.
  - `userdata_boot_set` now compares with the item the card holds.

### Round 2: the user's spec, "Start on just decides the start position on the carousel" (`edc59f1`, `9f6bb27`)

- **Start on never opens a page.** Every value powers on to home facing an item.
- **Choices:** Last place, then exactly the items home shows when Settings opens, in carousel order:
  - Recent and Favourites only while they hold games.
  - Each console only with games, so NES only with NES games.
  - SD card, NOR, Settings and Info.
  - The list comes from the registry (`nav_start_shown` → `settings_values.start_shown`), and LEFT/RIGHT skip what home doesn't show.
- **Stored by stable item code, not by list index.**
  - Slot 32 keeps `enum settings_start`'s codes: 0 Last place, 1 Recent, 3 Favourites, 4 SD card, 5 GBA, 6 GBC, 7 GB, 8 NES.
  - New codes: 9 NOR, 10 Settings, 11 Info.
  - Codes never change; a new item takes the next free code. Old values need no mapping: each still names its item.
  - The step order is `settings_start_order`; a host test checks it against the registry's items.
- **Fallback:** a chosen item home doesn't show (no NES games any more) gives Last place. If Last place's item isn't shown either, or was never set, home faces the first item.
- **Old Home (2) faces the first item.** That keeps what it meant ("home facing the first item"), and the tests' "Start on Home" routes keep working.
  - It still reads "Home" in Settings, but is no longer offered: stepping off it can't come back.
- **A stored but hidden choice stays stored** and still reads as its name ("NES"). The hint bar says "Not on home now: Last place instead.", and the choice works again once NES games come back.
- **Texts:**
  - Start on's explanation is "The item home faces at power-on."
  - New choices: "NOR", "Settings", "Info".
  - Info's Controls page gets a line under At power-on: "Home faces the item you were last on, or the one Settings' Start on picks."
  - README updated, and the roadmap's Settings line.

## Decisions the user may want to contest

- **Old Home (2) faces the first item** and reads "Home" until changed; it isn't offered any more. The alternative was to read it as Last place.
- **A hidden stored choice stays and reads as its name** ("NES"), with "Not on home now: Last place instead." in the hint bar. The alternative was to snap it to Last place.
- **Last place's own fallback is now the first item, not the nearest:** for example `@boot gb` after the last GB game is deleted. That follows the brief ("fall back to Last place, then the first item"); B10 had chosen the nearest.
- **Settings' choices are counted when the page opens.** A Rescan from inside Settings that adds or removes a console's games changes the list only when Settings is opened again.
- **NOR, Settings and Info can be chosen.** NOR always shows on home, even with no games.

## Bugs

- **Cart RAM session state, seen in your logs (pre-existing):**
  - The second boot of this build logged "previous session: nothing in cart RAM" after a session that ended in the menu, which should log "ended in the menu".
  - That session ran Settings → Rescan library and Identify library; something may clear SRAM page `0xF0`'s magic (`source/cartlog.c`).
  - Not reproduced.
- **The library index loaded from `library.bak`** on several boots. It may only be the two copies alternating; worth a look in v0.4.2.
- **A boot with no index yet** (the first scan failed): the consoles count 0 at power-on, so a chosen console falls back to Last place for that boot. This was already so before D1 (it faced the nearest item then).

## Changelog

- When you turn away from the item you powered on facing and come back (into another page and out, say), recent.txt is no longer rewritten with the same boot position. It is written only when the item differs from the one on the card. (8b7b1bc)
