## What was broken

**Nothing in where the menu starts.** Every Start on value starts where T19, as C3 changed it, says. That holds in the emulator through real power cycles, and on your cart.

- **Your cart's logs** (`/torii/logs`, copied read-only; boots of this exact build, id `F0044D26`) show each boot starting where its setting said:
  - Boot 1: Start on was **GBA** (set in an earlier build), so the GBA page opened. In Settings you then confirmed Home (28.9 s) and then **Favourites** (32.5 s); each confirm logged "nor: wrote the settings".
  - Boot 2: Start on was Favourites, so the Favourites page opened.
- **Last place was never the setting on this build.** Booting into a page (GBA, then Favourites) looks like the old "reopen the page" Last place, but it was a chosen item doing what T19 says.
  - The boot position itself was kept correctly the whole time: `@boot gb` was written 5 s after you left the GB page. Your card holds `@boot gb` now, so with Start on set to Last place you'd power on facing GB.
- **Emulator, end to end:**
  - Settings → Start on, saved on confirm (slot 32), then B at once: the next power-on uses it.
  - Last place after a real A-launch from the GBA page, the Recent page and the SD card page: home faces that item at the next power-on.
  - The in-game Reset hotkey (L+R+START) restarts the kernel facing Recent.
  - RIGHT on home, then 5 s of rest, then power-off: home faces the new item.
  - Every value 1–8 starts in the same place before and after a game.
- **The suspects the brief listed are all fine:**
  - `@boot` is set before a launch (`run_deferred` → `remember`). The launch's `userdata_recent_add` writes it with the list, so it isn't lost.
  - The idle flush writes it 300 frames after the last key.
  - Older `@boot gb 3` / `@boot home-gb 0` lines still read as their item.
  - The library index loads (or the first scan runs) before `nav_run` counts the items, so no console is hidden at start. If the index fails to load, a hidden item faces the nearest one. Nothing is written then, so the kept item survives.

**One real flaw, fixed (`8b7b1bc`):** C3's reported redundant write.

- `userdata_boot_set` compared a new item with the last one set, not with the one on the card. Opening the next item's page, leaving it and turning back rewrote recent.txt with the same `@boot` line at the idle flush.
- It now compares with the item recent.txt holds (`card_boot`, updated when the file is read or written).
- A real move is still always written: `boot_set` is "differs from the card" after every set, write and reload.

## Decisions the user may want to contest

- **A chosen Start on item opens its page** (T19, kept by C3): Start on GBA boots into the GBA list, not onto home facing GBA. That is why your boots opened GBA and then Favourites. If you'd rather every value face its item on home, as Last place does, it is a one-line change in `registry_start` (`open_or_face`).
- **Changing Start on to Last place leaves Settings facing Settings.** The next power-on then faces Settings, the item last faced.
