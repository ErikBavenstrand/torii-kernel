# Real-cart test of v0.2.0, 2026-10-18

The cart was an original Omega DE (black PCB EZODE, FPGA firmware 7, LX16 Rev.B), running the
v0.2.0 release with LOGGING at DEBUG. The test covered nine sessions and Diagnostics. The logs,
saves and RTS file are kept in `dist/cart-test-20261018/` (not committed).

## Results

- **Passed:** the kernel unit tests (17/17), the clock (a valid date, and it runs), PSRAM, NOR
  reads (CRCs of the FPGA images match), the save chip (read twice, unchanged), the SD write
  test and the buttons.
- **Games launched:**
  - Advance Wars from SD and from NOR (the NOR write worked);
  - WarioWare: Twisted!;
  - Pokémon Silver with Jagoomba Color;
  - Pokémon Emerald, with CLEAN BOOT and with ADDON (the in-game hook installed);
  - Crash Bandicoot XS (EEPROM).
- **Saves:** every save has the right size and a valid layout for its game. No save is
  corrupted or written under the wrong name. Emerald's save is still blank (all 0xFF), so its
  in-game save path wasn't exercised.

## Hardware facts learned

- WAITCNT is 0x0000 at boot. Both the kernel NOR and PSRAM read correctly at every WS0
  setting from 4/2 to 2/1 with prefetch, at the bus's own rate: 3640 KB/s at 4/2 up to
  4368 KB/s at 2/1 (20% faster), the same for both.
- `0x096A0000` bit 0 alone gates the clock: values 1 and 3 answer, 0 and 2 are silent.
- Rumble: pin 3 of the GPIO port didn't rumble at any register value (0–3).
- Cart RAM beyond the 128 KB save survives a soft reset but not a power cycle, so the crash dump,
  the session state and the in-game DEBUG snapshot survive only a soft reset or RESET.
- The crash handler works on hardware: Diagnostics' deliberate crash test was caught,
  dumped and reported on the next boot.
- **While SD mode is on, reads from cart ROM don't return NOR contents.** They return
  data left in the FPGA's SD buffer. Any SD write whose source buffer is in ROM writes that
  data instead.
- Speeds: SD reads 1710 KB/s, SD writes 200 KB/s (with a sync), BIOS LZ77 to WRAM 1083 KB/s,
  2344 cycles per glyph.
- EEPROM: with only the save type set in kernel mode (no game loaded), reads at 0x0DFFFF00
  returned `AAAA…` for save types 0x21 and 0x22 at both address widths. The EEPROM didn't
  answer, so the 512 vs 8K question is still open.

## What the user reported

- **Clock:** the clock on the checklist screen wasn't live. It looked stuck about 10 minutes
  behind.
- **In-game DEBUG:** after SAVE and LOAD, choosing DEBUG seemed to do nothing. The game came
  back at the save point and the cart was switched off, which erases the snapshot in cart RAM.
- **Not actually tested:** sleep, and NES (answered yes by mistake). Emerald was never saved
  in-game.
- **WarioWare: Twisted!:** can't be played on the Omega DE, because the game needs a motion
  sensor the cart doesn't have. Rumble in a rumble game is still untested (Drill Dozer would
  test it).

## Bugs found

1. **Log file filled with junk.** `start_file` (`source/tlog.c`) fills a new log with zeros
   from a ROM array, and on hardware that writes the SD buffer's leftover data (see above).
   `log_find_end` then finds the end in the wrong place, and the previous-line check reads
   junk. The text itself is intact, and saves and other files aren't affected. The emulated
   cart keeps serving NOR in SD mode, so no test caught it.
2. **Wrong symbol names in crash reports.** CI and macOS link the objects in a different order
   (GNU Make 4.1's unsorted `$(wildcard)`), so `just logs` names code from the wrong build.
   The boot line's build fingerprint can't tell the builds apart.
3. **The save flow isn't logged.** "Save sav?" decisions, save copies, NOR writes and
   settings saves leave no log lines. `Save_savefile` ignores write and close errors.
4. **Smaller ones:**
   - Diagnostics' summary doesn't name the failed checklist item.
   - The clock item shows a time that's already stale when you answer.
   - Rumble "no" answers are logged as errors.
   - After a crash, the next boot says the session "ended in the menu".
   - GB games show `(????)` for their code.
   - The checklist should say to use RESET, not power-off, before checking the DEBUG
     snapshot.
5. **The EEPROM probe** needs to run in game mode, e.g. from a test ROM, to answer anything.

## Emulator fixes

- The cart model's clock gate should be `rtcStatus & 1`.
- Cart RAM beyond the save should clear on a power cycle.
- ROM reads in SD mode should not return NOR contents, plus a test that log files are zero after
  their text.
- The EEPROM model shouldn't answer a probe the real cart doesn't answer.
